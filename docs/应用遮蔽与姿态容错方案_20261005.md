# 视界盾：应用遮蔽、即时偏好与机主姿态容错

本版先确定应用边界，再按应用策略保护。主界面直接提供三个独立选项：遮蔽范围模糊化、检测陌生人后弹窗、检测陌生人后音效。可以组合使用，运行中修改通过本机通信传给后台，无需重新加载摄像头与OCR模型。

## 一、实际操作

1. 打开软件，由本人在设置中登记机主，已有模板继续使用。
2. 勾选防护效果，启用防护。主界面三个勾选框修改后立即保存。关闭遮蔽时保留检测与所选提醒。
3. 聊天应用先暂停防护，打开目标窗口并保持常用布局；打开设置，点击“校准聊天对话区域”。
4. 在聊天窗口拖动框选消息历史及输入框。要保护会话标题、附件预览时，一并纳入。风险期间保护框内全部内容，导航区域可排除。
5. 窗口平移后自动跟随。客户区尺寸变化超过2%或2像素容差时，校准失效并暂时整窗保护；使用新布局时重新校准。
6. 图片、表格或特殊软件可点击“指定应用整窗保护”，再点击目标窗口。
7. “清除应用校准”恢复默认策略。这三个校准按钮完成后直接保存；设置页“取消”不撤销已经完成的校准或清除，只取消普通设置的未保存修改。
8. 校准保存进程名、窗口类、区域比例和客户区尺寸，不保存截图、聊天文字、窗口标题或面部数据。
9. 暂停、退出清理遮罩及后台模型进程；关闭主窗口驻留托盘。

同一进程和窗口类共用校准。软件版本、侧栏展开、通讯录/设置页切换可能改变内部布局，即使外部尺寸没有变化也要重新校准或采用整窗保护。当前没有自动判定所有第三方客户端的语义布局，不能把一次校准描述成全版本自动适配。

## 二、按应用选择策略

| 类别 | 当前行为 | 保护范围及处理建议 |
|---|---|---|
| 微信、QQ、TIM、钉钉、飞书、Teams、Telegram、Discord | 风险期间对话区保护；没有有效校准时整窗保护 | 消息历史、输入框、会话标题、附件预览；联系人栏按需求排除，含隐私的群成员栏应纳入 |
| Photos、PhotoViewer、Photoshop、GIMP、Paint.NET、画图、ImageGlass、IrfanView | 整个应用窗口模糊化，不依赖OCR | 图片即使没有文字也保护；另开预览和不同进程须分别验证 |
| Excel、WPS、ET、Acrobat、AcroRd32 | 整个应用窗口模糊化 | 工作簿、表格、PDF与工具区一起保护；WPS不同文档共用进程时先采用保守策略 |
| Word、记事本、编辑器及未配置应用 | 敏感行及待分析区域裁剪到应用窗口 | OCR异常或过期时扩大到窗口；全文私人内容可指定整窗保护 |
| 浏览器 | 默认敏感行策略，支持指定整窗或校准区域 | 浏览器进程无法区分网站。网页布局改变或切换网站后旧校准可能失效，推荐整窗保护私人网页 |
| 密码、财务、业务工具 | 可指定整窗保护 | 软件不在名单时应显式指定；密码控件不可见内容不会通过UIA读取 |
| 游戏、视频、远程桌面、全屏演示 | 默认可见窗口策略，推荐指定整窗 | 独占全屏、受保护视频和特殊渲染路径尚需分别验证 |
| 系统任务栏、桌面、软件自身 | 不当作普通应用遮盖 | 保留暂停、退出入口。枚举失败、坐标异常等紧急情况仍允许全屏保护 |

默认名单按进程名匹配。新版应用改名时，用“指定应用整窗保护”补齐。旧式UWP宿主ApplicationFrameHost不根据宿主名直接归类为图片应用，以免误分类其他软件。聊天类别没有有效校准时整窗保护，不使用固定左右百分比猜测消息区。

## 三、区域计算与显示

后端启用每显示器DPI感知，采集和窗口边界均采用物理像素，绘制时转换成Qt逻辑坐标。区域校准以客户区为参考，避免标题栏高度影响定位。窗口裁剪到主显示器；当前仍只支持主显示器保护。

枚举按前景到背景处理。背景应用遮罩减去前景窗口覆盖的区域，避免把前景其他应用或控制面板一起模糊化。输入穿透系统浮层不算真正的应用遮挡。应用范围绘制不额外膨胀，防止统一边距越过对话区或前景边界。

```text
摄像头风险 + 当前桌面帧
    → OCR敏感行与变化区域有效性检查
    → 可见应用边界及类别
    → 默认策略 + 用户校准/整窗覆盖
    → 扣除前景窗口覆盖并裁剪到主屏
    → 不透明强像素化、模糊、压暗
    → 风险持续消失后延时恢复
```

聊天、图片的区域策略保护全部指定内容，不等待手机号等规则命中。其他应用仍只声称保护规则覆盖的敏感信息，尚不能理解所有私人聊天语义。变化区域的临时遮蔽限定在应用内，减少随机桌面块。

原始桌面及模糊图只保留当前有效内存版本。首次开启遮蔽仍实测捕获排除；运行中从纯提示切换为遮蔽，先执行排除探针再启用遮罩。验证失败显示异常，不能宣称已正常保护。变化内容检测发生在呈现之后，仍需实测端到端短暂暴露时间。

## 四、机主姿态与陌生人区分

继续使用YuNet检测、SFace特征比较和本地永久模板。日常不自动登记路人，不把每帧特征写入模板。

| 情况 | 当前行为 |
|---|---|
| 首次启用或会话失效 | 连续5次可靠匹配后确认机主，此前保护 |
| 已确认机主短暂低头、偏头或脸不清晰 | 最后一次可靠匹配起最多2秒姿态宽限；当前帧仍标为身份未确认 |
| 低质量脸留在原位置附近 | 可以使用有界宽限；仅可靠匹配能续期，低质量帧不能无限延期 |
| 宽限内本人重新可靠匹配 | 自动恢复当前确认，无需重新登记 |
| 多人进入 | 立即请求保护，优先于姿态宽限 |
| 正面清晰脸明显不匹配本人 | 立即请求保护，优先于姿态宽限 |
| 低质量脸位置明显跳变或轨迹不可靠 | 撤销宽限，重新确认 |
| 无脸或不确定持续超过2秒 | 请求保护，等待自动重新确认 |
| 摄像头退出、故障、状态超过1.5秒 | 异常保护，不使用姿态宽限 |
| 未登记 | 提示登记并保护，不发“识别陌生人”提醒 |

当前可靠匹配阈值0.45；正面清晰脸相似度低于0.25为明确不同身份，其余不确定状态最多使用有界宽限。正面条件由眼鼻关键点几何判断。阈值必须结合本队实人、摄像头和光照评估，模拟序列不能证明真实准确率。

宽限期完全看不到脸时不能直接验证本人。陌生人只显示模糊侧脸、刻意遮挡或完全在摄像头视野外仍可能无法判断；长期低头超过宽限仍会保护，这是明确的产品行为。需要较长时间低头时可选择仅提示，但系统不能由无脸状态确认视野外没有旁人。

弹窗及音效只在陌生人/多人状态进入时触发。启动、未登记、机主失去确认和系统异常继续显示状态，不播放陌生人提醒。提醒事件有10秒冷却，遮蔽不等待冷却。

## 五、精确自动适配的下一阶段

当前交付应用分类、明确校准和保守回退。自动对话区定位应按具体应用版本验证，不能直接用固定比例替代校准。

1. 标准控件客户端：在独立UIA进程获取可见消息列表、Document、Edit、Pane公开角色及BoundingRectangle；确认消息容器与输入框属于同一会话，再输出范围。
2. 自绘聊天客户端：先验证可访问树完整性；无可靠边界时保留校准。若增加布局检测模型，应标注消息、联系人、输入框、附件区，并对软件版本划分独立测试集。
3. 网页聊天：结合域名、页面可访问角色及布局签名；切换网站立即作废旧适配。纯浏览器进程名不能区分聊天、搜索和办公。
4. 图片/PDF：优先整窗保护，覆盖文件名、缩略图、浮动预览；细分画布之前验证工具区是否含隐私。
5. 文档/表格：结合可见段落、单元格、敏感规则与文档级策略，测试滚动、冻结窗格、缩放和多窗口。
6. 多显示器：每屏独立捕获和遮罩，跨屏窗口拆分；不能直接平移主屏坐标。
7. 窗口事件同步：前景切换、位置及布局变化提前使范围失效。仍须测量捕获、布局、风险和显示链路的时序差。

适配器输出应用/窗口标识、消息区、输入区、测量时刻、布局签名、置信度及有效条件。置信度不足、超时或布局变化必须回退，不能使用推测区域。取得特定客户端的实测证据后，再逐步减少手动校准。

## 六、联合验收与分工

| 项目 | A | B | C |
|---|---|---|---|
| 姿态容错 | 模板和阈值评估 | 显示当前确认/宽限/异常 | 实测0.5、1、2、3秒低头，左右转头、眼镜、背光 |
| 陌生人 | 替换机主、多人、远近、小脸 | 提醒与遮蔽独立 | 记录误保护、漏保护、实际端到端延迟 |
| 聊天范围 | 输出稳定风险状态 | 校准、移动、输入、滚动、侧栏 | 按软件版本验证消息保护、导航可见 |
| 图片范围 | 同上 | 全窗及浮动预览、遮挡处理 | 无文字图片也保护，切前景不误遮 |
| 即时偏好 | 风险持续不丢状态 | 运行中切换、保存、托盘 | 开关确认、取消、无托盘提示、长时运行 |
| 分发 | 不打入个人模板 | 完整exe及依赖目录 | 新电脑、不同DPI、CPU/GPU和用户目录 |

实人结果和模拟结果分别记录。单元测试验证状态与几何，包测试验证依赖、并行、进程和捕获排除；二者均不能替代具体聊天客户端及机主姿态的联合验收。

# 软件架构与后台运行

统一入口为`VisionShield.py`，前端使用原生PySide6控件，主界面保留防护开关、机主与旁观状态、范围摘要、模糊／深色切换、水平强度滑杆、设置和后台运行。设置中遮蔽、音效、弹窗独立选择，可设置打开软件后的自动启用及托盘驻留偏好。首次登记必须由本人明确操作。

## 前后端生命周期

图标的单一设计源是`assets/VisionShield.svg`，原生窗口、托盘和启动页共用多尺寸图标。`packaging/generate_icon.py`从同一SVG生成EXE使用的ICO，构建脚本自动执行。修改图标后需要重新构建软件，旧EXE不会自动改变。

首次前台打开提供约1秒的品牌淡入／淡出与细线动效，结束后释放启动窗口并显示主界面。点击可跳过；直接驻留托盘的启动和重复唤回窗口不再次播放。动画仅表示打开界面，不提前加载模型，也不显示虚假的模型加载百分比；自动启用防护在进入主界面后按既有设置执行。

`app_shell.py`负责界面、托盘、设置和后端进程管理。启动和暂停时不加载图像库及识别模型；启用后通过`guard_service.py`启动独立后端，摄像头和OCR并行工作。前后端通过本机Qt通道传递结构化状态和设置，不传输人脸图像或OCR原文。暂停停止采集与推理，退出等待资源清理；关闭主窗口通常驻留托盘，无托盘时关闭会停止软件。

`camera_worker.py`配合YuNet、SFace、跟踪和身份状态判断机主及旁观风险；没有模板、机主未确认、多人、异常或状态过期时请求保护。机主短暂低头后可以重新验证，不需要重新登记。严重模糊、遮挡和远处小脸仍可能影响检测。

`screen_capture.py`采集主显示器，`fast_ocr.py`和`ocr_worker.py`执行本地ONNX文字检测与识别，`sensitive_rules.py`按格式、校验和上下文标签判断敏感信息。`content_index.py`和`content_state.py`管理变化区域、结果时效和有效坐标，避免将旧敏感框用于已经变化的桌面。

## 保护策略与交互

已有用户范围时仅处理有效局部或所点整窗，不叠加其他应用默认遮蔽。新框选以窗口客户区相对位置绑定，不依赖控件或图像特征；窗口移动和缩放时选区随动，内部布局改变需重选。局部OCR开关默认关闭，开启后仅处理选区内命中及待分析部分；不改变整窗策略。窗口绑定或选区失效不扩大到整屏，软件重启后需重新选择。没有用户范围时保留自动应用保护。风险稳定消失并有连续新鲜的安全观察后恢复，默认等待1秒。

模糊强度在主界面水平滑杆上调整，向右增强，较弱模糊可能仍可读；重要内容可选择不透明深色遮挡。OpenCL不可用时滤波回退CPU，DirectML不可用时OCR回退CPU。范围、默认应用策略、帧有效性及提醒行为见[动态桌面防护](动态桌面防护与显示模式.md)。普通屏幕的遮罩对机主也可见，不是按观看角度显示的硬件防窥。

风险提醒受冷却时间控制，音效和系统通知可能受到静音或通知设置影响，保护逻辑不依赖提醒是否播放。软件不默认显示实时摄像头或OCR预览、不积累聊天原文历史。

## 用户数据和运行

发行版模板和运行元数据位于当前Windows用户的`%LOCALAPPDATA%\VisionShield`，设置使用QSettings。默认不保存画面或原文；机主特征模板仍是需要保护的本机数据，当前未增加应用层加密，不应上传仓库或随软件包分发。源码模式保留模块内原有本机数据路径。

开发环境和启动见[协作指南](协作启动与同步.md)。只预览界面可执行`python VisionShield.py --preview`，不启用摄像头或识别模型。软件下载与更新见[下载指南](下载与版本更新.md)。前端低占用不代表整个识别系统低占用，当前完整后端峰值约1.9GB，后续仍需优化及设备验收。

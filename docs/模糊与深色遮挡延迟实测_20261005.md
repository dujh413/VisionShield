# 模糊与深色遮挡延迟实测（2026-10-05）

测试生产源码：main `49c04ad2b4d82bbd052a13e68ddc80a0ff242cfd`（PR #10 已合并）。本次新增的是复现脚本与测试报告，未修改产品运行逻辑。以下为本机实际运行得到的 CPU / Qt 离屏成绩，不能代替生产 DirectML 与真实设备端到端验收。

## 测试环境与方法

- Intel Core i9-14900HX；Windows；Python 3.12.14；ONNX Runtime 1.30.0；RapidOCR 1.4.4 的同一组 PP-OCRv4 本地权重；PySide6 6.11.2。
- 实际检测、识别均为 CPUExecutionProvider；当前环境没有启用 DirectML。遮罩使用产品的 NumPy 精确盒式模糊及真实 Qt raster 绘制，默认模糊半径 8 物理像素，抹黑输入为“遮挡”。
- 分辨率 2560×1600，8 行虚构文字；两处验证码变化，包含虚构手机号和邮箱。直接使用生产 OCRWorker（独立子进程与 IPC）、IncrementalOCR、ContentState、OverlayWindow；每 20ms 查询结果/后台模糊，预热 3 帧后计 30 帧。保留每 8 次局部更新后的整屏刷新，因此统计含 full 和 partial。
- “合成帧到最终 Qt 效果”从帧生成完成后开始，包含区域变更校验、实际 OCR/IPC、结果接受、后台模糊及 Qt 绘制；“遮罩指令到最终效果”单独排除 OCR 和 ContentState。样本构造、图像副本准备不计时。
- 6 个敏感区域的遮罩覆盖面积为 4.40%。密集样本为 140 个 900×18 文字框，默认 padding=8 将相邻框合成两个大区域，总面积 69.42%；全屏样本覆盖 100%。遮罩测试每轮失效旧缓存，不是静态复用成绩；小区域计 30 次，密集/全屏计 10 次，各预热 3 次。
- 风险信号预设为已发生。没有启动真实截图采集、摄像头或应用区域追踪；Qt 离屏窗只使用生成的图像，采集排除探针只在该测试窗构造时绕过，产品逻辑未改变。未测试 DWM 合成、显示器输出、刷新率或真实陌生人检测。

实际运行还包括 100ms 采集周期、20ms 控制回调、摄像头判断及应用追踪；未测的这些环节不能以固定数值补齐为“真实端到端”。paintEvent 结束也不等于显示器像素已更新。

## 动态文字到最终效果

表格单元格依次为 **中位 / P95 / 最大，单位 ms**。P95 表示这批样本约 95% 不超过该值，不是所有场景保证。

| 项目（各 30 帧） | 深色遮挡 | 盒式模糊 r=8 |
|---|---:|---:|
| 合成帧到最新文字确认与最终 Qt 效果 | 308.37 / 468.89 / 470.30 | 315.13 / 504.19 / 513.72 |
| 合成帧到第一层保护绘制 | 11.52 / 11.91 / 11.95 | 11.79 / 12.45 / 12.59 |
| OCR 子进程处理（差分与推理） | 235.00 / 399.25 / 422.00 | 234.50 / 399.25 / 406.00 |
| 结果接受/区域校验 | 8.44 / 8.78 / 9.56 | 8.33 / 8.54 / 8.79 |

两种模式均保留全部 8 行识别结果、6 行敏感内容，并正确更新两个验证码。局部处理面积中位为 6.253%，含周期整屏刷新。模糊等待时先绘制不透明深色回退，而不是等待完整 OCR 或模糊完成后才保护。

这里两个总耗时中位数仅相差约 7ms，但不能把它当作独立模糊计算成本：后台模糊、OCR 和等待结果会交叠。该少量文字样本仍以 OCR 为主要开销。

## 单独遮罩处理

计时从收到遮罩指令到指定最终效果完成 Qt 绘制，包括几何整理、复制所需区域、后台工作及 20ms 结果查询，不包含 OCR、IPC、ContentState 或物理显示输出。

| 场景 | 深色遮挡（中位 / P95 / 最大 ms） | 盒式模糊 r=8（中位 / P95 / 最大 ms） |
|---|---:|---:|
| 6 个敏感区域，4.40% 面积，30 次 | 0.43 / 0.59 / 0.66 | 22.37 / 43.13 / 43.30 |
| 140 行密集框，合并后 69.42% 面积，10 次 | 0.90 / 1.10 / 1.10 | 628.84 / 630.23 / 630.33 |
| 全屏保护，100% 面积，10 次 | 0.85 / 1.32 / 1.36 | 833.08 / 883.03 / 890.97 |

模糊后台纯计算中位分别为 18.32ms、602.92ms、814.72ms。密集/全屏模式首次深色回退中位仅 2.67 / 2.69ms；最终模糊完成较慢，回退期间已有保护。这些数值不包含等待下一次真实采集或控制回调的时间。

密集区域的模糊是显著性能压力：当前盒式模糊使用 float64 的两次累计和及中间数组，大面积输入增加扫描、分配与内存带宽开销。140 行不是 140 个小模糊块；重叠 padding 合并后接近 70% 屏幕，解释了为什么同样半径会达到约 0.63 秒。全屏约 0.83 秒。在持续变化场景中，完成结果还必须通过当前像素核对，过时结果不能直接显示；本轮没有统计连续变化下最终模糊保持有效的帧率。

## 半径与冷启动

同样 6 个敏感区域、各 30 次，最终模糊效果：

| 半径（物理像素） | 中位 / P95 / 最大 ms |
|---|---:|
| 8 | 22.37 / 43.13 / 43.30 |
| 16 | 22.28 / 42.65 / 43.81 |
| 32 | 22.63 / 54.01 / 64.32 |

本批样本中位均约 22–23ms，覆盖面积比缩小半径更影响开销；P95 会受后台调度和 20ms 查询周期影响，不能据此保证任意半径都一样快。

每个模式只测一次模型进程冷启动，不计算冷启动 P95：深色遮挡模型 ready=1904.93ms，首次整屏帧=680.42ms；模糊模型 ready=1886.51ms，首次整屏帧=966.77ms。首次帧从模型 ready 后开始计，表内 30 帧已剔除该首次帧及 3 帧预热。这里不是整个软件或摄像头的启动耗时。

## 复现与结论

在已准备相同依赖与公开本地 OCR 权重的桌面模块目录运行，输出文件留在忽略的 records，不上传运行数据：

```powershell
.\.venv\Scripts\python.exe benchmark_effect_latency.py --samples 30 --large-samples 10 --output records\effect_latency.json
```

请先创建 records 目录。脚本会打印实际 provider；若运行环境启用 DirectML，所得 OCR 成绩应单独报告。源码不下载模型，不读取真实桌面/摄像头，不导出识别原文或图像。进程退出验证确保 OCR 结束，遮罩线程被关闭。另用 2 次短复核验证各场景绘制像素为不透明，深色颜色正确，全部 6 行敏感内容受到保护；该短复核没有替代上述 30/10 次性能数据。

抹黑的显示处理接近 1ms，当前更适合要求低延迟的大面积保护。少量敏感框的最终模糊约 22ms，识别仍占主要开销；密集/全屏盒式模糊是下一项明确的优化目标，可评估同等边界和取整结果下的原生滤波实现及减少大数组分配。测试不证明所有应用准确率、GPU性能或真实设备端到端延迟，未重建 exe。

# 视界盾体验修复测试报告

## 本轮修复

- 主界面直接设置模糊化、陌生人弹窗、陌生人音效，独立保存；运行中改变遮蔽通过本机JSON通信生效，模型进程不重启。
- 启动前收到的偏好会保留；通信支持逐行拆包；捕获探针的嵌套事件循环不会并发重复执行偏好更新；立即停止流程保留。
- 增加应用类别、聊天区校准、整窗指定、前景遮挡扣除；取消统一外扩对精确范围的侵入。
- 已确认机主短时低头/偏头使用最多2秒宽限，明确异人、多人、位置跳变和故障不继承宽限。
- 未登记、普通姿态丢失及异常不再发陌生人弹窗/音效。
- 校准配置损坏会退回默认策略；分发仍排除个人模板、截图、原文与模型缓存。

环境：Windows 11 x64，AMD Ryzen 7 7745HX，RTX 4070 Laptop，本机主屏2560×1600、150%缩放；Python 3.12、PySide6 6.11.2、OpenCV 4.10.0、ONNX Runtime DirectML 1.24.4。

本人已授权配合摄像头测试：使用打包版用户目录中的已有模板，采集约80秒、661个状态样本，无摄像头异常；没有保存照片或改写模板。按预告时间划分的短低头时段141个样本中32个使用姿态宽限，保护请求为0；偏头时段140个样本中28个使用宽限，5个触发保护，原因是一次失去确认持续超过2秒；恢复人脸后自动重新确认。正面阶段也出现检测器间歇丢脸，宽限避免了大部分即时保护。

这轮最多检测到1张脸，未观察到陌生人事件。用户已反馈仅完成本人低头、偏头，因此后半段按计划命名的“旁人时段”不是多人测试。本人动作结果说明短时容错生效，也说明超过2秒的动作仍可能触发；不宣称所有低头/偏头均不遮蔽。模拟序列另外验证“明确异人/多人优先于宽限”，实人旁人进入仍待联合测试。微信/QQ等具体版本的对话区域仍需按方案校准和实测，原生虚构窗口几何测试不能替代客户端验收。

## 交付与后续

本轮exe位置为 `dist/windows-experience-r2-20261005/VisionShield/VisionShield.exe`。必须保留同目录 `_internal`，发布旧exe不会自动更新。源代码、打包配置、测试与详细方案同步到私有任务分支，安装包和本机测试证据不上传。

使用时先校准聊天区域，开启需要的防护效果，再启用防护。明确姿态联合验收需依次进行：正面确认、低头1秒回正、偏头1秒回正、持续低头3秒、机主与旁人同框、机主离开后旁人进入。分别记录状态、误保护、漏保护和端到端时间；不保存真实人脸或聊天截图。

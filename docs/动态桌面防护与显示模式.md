# 动态桌面防护与显示模式

## 当前界面操作

使用统一入口 `VisionShield.py` 或重新构建后的软件，勾选“风险时遮蔽保护范围”，在主界面选择“模糊”或“深色”，再点击“启用防护”。模糊通过水平滑杆调整，向右拖动使文字更难辨认；界面显示较弱、适中、较强，无需填写数字。效果和强度支持运行中修改，滑杆输入短暂合并后即时应用并保存；立即退出时也会保存最新选择。首次默认使用适中模糊。关闭遮蔽开关后保留检测与提示，屏幕内容保持可见。

| 用户选择 | 行为 |
|---|---|
| 模糊＋强度滑杆 | 在有效保护范围内显示模糊；向右拖动增强 |
| 深色遮挡 | 使用不透明深色矩形覆盖有效保护范围 |
| 关闭“风险时遮蔽保护范围” | 只检测与提示，不绘制遮罩 |

内部盒式滤波使用边长 `2r+1` 的均匀平均核，滑杆对应2–64物理像素半径，默认24。前后端仍保留 `effect_text` 字符串协议：数字表示模糊，`遮挡`表示深色，空字符串表示明确关闭。主界面已移除文本输入；旧整数配置规范化并限制在滑杆范围，旧空值迁移为默认模糊，防止已经勾选遮蔽却实际不处理。独立开发控制面板另提供明确的“不遮蔽（仅检测与提示）”选项。

模糊自动优先使用GPU，通过显卡驱动提供的OpenCL均匀滤波计算，边缘复制；GPU不可用或运行故障时回退CPU。GPU与CPU滤波回退路径保留自动测试，实际设备性能另行验收。

显示模式与风险触发逻辑配合：机主未确认、旁观风险或身份连接失效时处理保护范围；可靠安全状态持续后恢复。关闭遮蔽后，即使出现未知内容或异常也不绘制遮罩，采集、规则和状态诊断仍可运行。

暂停防护并打开目标应用，在设置中选择“框选局部区域”或“选择整个窗口”。新局部选区直接绑定该窗口句柄、进程及客户区相对位置，不再要求控件锚点或稳定图像特征，纯文字和空白区域也可选择。选区随窗口移动和缩放；窗口内部布局重排或切换页面后，应重新框选。整窗保护只处理所点窗口的可见范围。每个应用仅保存一个范围，重新选择会替换先前范围。窗口关闭、绑定失效或旧版追踪失配时暂停该选区并提示重新选择，不扩大到整窗或整屏。窗口绑定不持久化，软件重启后局部和整窗都需重新选择，不自动接管同应用的其他窗口。旧版控件／视觉追踪配置仍兼容，更新后建议重新框选以使用新的窗口相对选区。

设置中的“框选区域内自动识别敏感内容”默认关闭，支持运行中保存并即时生效。关闭时，风险出现便处理整个有效局部选区；开启时，仅将本地OCR有效敏感命中的文字框与选区求交。其余保持清晰，加载、超时、识别未完成、未命中或仅“无法确定”标签时都不整区遮盖；已失效的旧框不继续显示。这意味着等待识别及漏检的内容不会自动保护，需要完整覆盖时可关闭该选项。手机号、邮箱、身份证校验及验证码、账号、姓名、地址等标签关联沿用`sensitive_rules.py`，尚未实现通用私人聊天语义识别。该选项不改变整窗策略，也不扩大到其他应用。

局部模式先裁出有效选区再调用OCR，坐标随后映射回主显示器。小选区保留输入像素，避免先缩小整屏而损失小字；很大的选区仍受检测模型输入尺寸限制。各选区的增量缓存最多20个，移出当前范围的缓存立即清理。没有有效绑定时不退回整屏；范围变化后拒绝旧范围返回结果。其他应用的变化不会使选区模型反复推理相同文字。状态显示实际读取行数和有效敏感条数，范围失效时提示暂停后重新框选。

已复现并修复“文字未变化、附近光标闪烁却清空敏感框”的问题。直接匹配的手机号、邮箱及通过校验的身份证号，以其文字框内的精确像素和OCR未完成标记验证；邻近变化区的扩边不再抹去这些命中。文字本身任一字符变化仍会使旧命中失效；验证码、账号等依赖标签的值继续验证周围上下文。手机号支持空格、连字符、点号分组；不把普通日期或更长数字串当作手机号。

模糊不向范围之外添加边距，也不填满被排除的前景窗口空洞；主程序的控制窗口不被遮蔽。窗口枚举计算稳定的保护范围与扣除前景后的可见范围，模糊在稳定范围内后台更新，绘制时按可见范围裁剪，前景拖动不再因遮挡矩形拆分而清空整个模糊缓存。完全被其他窗口遮挡时，遮罩透明但继续更新有效选区的模糊，移开遮挡后复用缓存。风险解除而隐藏遮罩时清除画面和结果引用，保留工作线程及GPU上下文；暂停、退出或显示器尺寸变化时释放。

目标窗口自身连续移动时，新位置可能还没有对应的屏幕截图，不能直接采样旧截图中新位置的桌面背景。整窗及关闭局部OCR的窗口相对选区会把已有不透明模糊片随窗口平移，拖动中冻结其内容；窗口位置停稳50ms之后取得的新截图，才用于更新模糊。这个窗口绑定的平移复用与普通250ms画面变化桥接不同：拖动期间可以持续，但只适用于同一窗口、进程、选区配置、尺寸和强度；不复用到其他窗口，不延长OCR坐标有效期。收到停稳后的新帧后，以不超过250ms的过渡等待后台结果替换。改变范围尺寸、绑定、强度或效果会失效，首次加载或渲染异常时仍可能在有效保护范围内使用深色临时保护；局部OCR未命中时不产生这样的整区保护。

范围选择或清除按钮会先保存设置页当前选项并立即应用；普通取消不保存尚未提交的表单。清除全部范围后恢复默认应用与内容策略，需限定范围时应保留有效选区。其他效果选择可分别使用，不会强制打开已经关闭的遮蔽开关。

模糊计算在后台进行，队列只保留最新请求。首次结果未准备好时仅在有效范围使用深色覆盖；连续变化时尽量保留相同范围的有效模糊，并更新最新结果，减少黑帧切换。出现范围变化、失效或异常时重新核验范围，不以临时整屏遮蔽替代定位。

## 动态画面与有效性

- OCR结果不再要求整屏像素完全相同。对未变化区域保留有效结果，对变化区域及关联文字行标记待分析；标签变化也使邻近值行失效。默认自动策略可临时保护未知区域，局部OCR模式只绘制有效敏感命中，不把未知区域转成整区遮盖。
- 差分使用精确像素比较，不忽略单字符变化。远距离小变化分别裁剪；面积、区域数量过大或达到刷新条件时重新执行整屏OCR识别。识别范围不等于遮蔽范围，遮蔽仍限于已确认的应用/选区。
- 采集超过1.5秒未更新时不复用旧坐标。OCR快照超过10秒失效，拒绝未来时间、过期或倒序结果；稳定画面按5秒间隔重新提交，并定期整屏刷新。
- 空检测结果标记为未知，不作为没有敏感内容的完整性证明；局部OCR模式此时保持清晰并提示等待识别。
- 身份消息要求有限且近期的发送时间；新会话在旧会话超时后接管，已经退休的会话不能再次覆盖状态。这个本机接口仍不构成身份认证边界。

以上阈值是当前原型默认值，需要按目标设备和场景验证。区域像素验证、OCR覆盖状态和实际模型漏检是不同问题，不能将有效缓存当作全部文字已被识别的证明。

## 诊断与复测

以下命令在仓库根目录及已准备依赖、模型的环境中执行：

```powershell
.\视界盾桌面防护\.venv\Scripts\python.exe .\VisionShield.py --diagnostics
```

选择模糊并拖动滑杆后启用。使用虚构内容，分别检查单字符修改、光标闪烁、两个远距离区域变化、滚动、窗口移动、暂停与重试；运行中切换深色遮挡，关闭遮蔽开关后确认内容保持原样。另检查局部/整窗选择后范围外始终清晰、定位丢失时暂停选区遮蔽、立即退出再打开后保留滑杆选择。统一入口自动启动摄像头与OCR；只有独立开发控制面板需要另行运行身份发送器。

源码诊断日志在本模块忽略的 `records` 下；打包软件位于当前用户的 `LOCALAPPDATA/VisionShield/records`。包含状态CSV、每秒心跳和OCR元数据事件。记录每个返回结果是否接受、模式、区域数量、截图年龄、采集耗时、队列等待、差分、预处理、检测、裁剪和识别；心跳也记录最近模糊工作的实际后端 `blur_backend`、设备、GPU核心耗时及简短回退代码，连同提交模式和半径。`opencl-gpu`仅在实际GPU核心完成并通过事件计时后记录；`blur_gpu_ms`不包含传输，`blur_ms`包含后台初始化及传输。状态CSV中的OCR耗时不再仅限被接受的结果。不要上传设备日志、截图、文字原文或面部模板。

日志中的计时没有覆盖显示器实际扫描输出，不能直接称为实际保护生效耗时。当前已在RTX4060验证GPU模糊和合成Qt流程，真实桌面体验仍需在运行设备上复测；本改动没有替换OCR模型、引入TensorRT或实现共享内存传帧。

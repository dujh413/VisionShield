## 1. 项目方向与核心调整

视界盾面向校园公共学习空间中的敏感材料查看与核对任务，利用普通摄像头感知可能的旁观风险，自动隐藏指定敏感内容，结合内容历史与用户操作控制恢复。项目围绕“用户为何需要保护、当前做法有哪些不足、技术如何适配任务、实际效果怎样”组织实施与证据。

**项目主线：场景调研 → 任务与需求定义 → AI 环境感知 → 内容分级保护 → 完整任务验证 → 小规模试用与推广评估。**

| 设计方面 | 本方案的场景赛安排 |
|---|---|
| 项目定位 | 公共学习空间敏感材料任务的保护方案 |
| 服务对象 | 在图书馆、自习室等场所使用电脑的学生 |
| 核心任务 | 查看、核对、填写并反复返回敏感字段 |
| 技术作用 | 根据环境风险和展示历史控制局部隐藏与恢复 |
| 场景创新 | 验证对重复查看流程的改进，体现需求与技术适配 |
| 主要证据 | 调研记录、需求对应表、真实位置任务实验、用户反馈 |
| 实施成果 | 可运行原型、场景实施记录及可复核效果数据 |

本方案专用于场景创新赛题，章节、验收和材料均按该赛题组织。

## 3. 场景定义与用户任务

### 3.1 场景选择

首期选择“学生在公共学习空间查看与核对含敏感字段的个人材料”。场所可为图书馆、自习室或其他获准测试的公共学习环境。通过调研确定实际发生的任务和保护对象。

| 场景要素 | 定义 |
|---|---|
| 使用者 | 在公共空间使用笔记本电脑的学生 |
| 工作内容 | 查看、核对或填写材料中的个人字段 |
| 敏感对象 | 联系方式、地址、个人申请信息等，由用户确认 |
| 环境变化 | 人员经过、邻座活动、短时靠近、反复朝向屏幕 |
| 重复展示 | 滚动查找、返回核对、切换页面后继续查看 |
| 任务目标 | 完成规定核对或填写，减少敏感内容旁观暴露 |
| 实验内容 | 虚构材料、随机字符与虚构关键词 |

不以真实私密材料作为实验输入。调研中记录任务类别和操作习惯，无需收集个人秘密或原始私密截图。

### 3.2 场景中的待验证问题

1. 用户是否经常在这些环境处理需要隐藏的内容？
2. 人员活动是否会引起频繁切换、最小化或手动遮挡？
3. 敏感字段是否会在同一任务中反复出现？
4. 用户是否接受摄像头持续工作，以及怎样的提示和数据处理？
5. 自动保护是否能改善任务，而不是让用户更频繁地解除保护？

这些问题在调研与实验前属于假设。若重复查看需求薄弱，应根据真实调研收窄任务或调整候选场所，并更新场景定义。

### 3.3 完整任务示例

参与者打开一份虚构个人申请材料，在多个页面中查找联系方式、核对两个字段、填写指定答案，再返回前页确认。过程中设置无旁观、人员经过、连续观察和多次短观察条件。

每项任务都有答案、起止点和完成判定，可同时测量旁观者辨认、使用者时间与错误。

## 4. 需求分析与调研方法

### 4.1 调研设计

首先邀请约 8—12 名目标用户开展半结构访谈，作为首轮工作量目标。条件允许时观察其使用虚构材料完成代表性任务。招募覆盖不同座位习惯、电脑使用经验和隐私偏好，记录来源与选择方式。

| 问题方向 | 调研内容 | 对设计的影响 |
|---|---|---|
| 任务发生 | 最近是否发生、地点、内容类别、反复查看情况 | 确定场景与任务频率 |
| 当前保护 | 最小化、调整窗口、改变姿势或其他做法 | 设置传统做法基线 |
| 操作负担 | 中断、重新查找、忘记恢复、重复输入 | 确定任务成本指标 |
| 保护范围 | 哪些字段需要隐藏，哪些可以保留 | 设计内容分级 |
| 摄像头接受 | 持续使用、状态提示、视频存储顾虑 | 设计主动启用和本地处理 |
| 恢复偏好 | 自动恢复、按住查看、短时展示 | 确定交互与等待方式 |

### 4.2 需求—设计—指标对应

| 候选需求 | 方案设计 | 验证指标 |
|---|---|---|
| 人员活动时减少手动切换 | 后台感知与自动保护 | 手动切换次数、任务时间 |
| 保留材料上下文 | 仅隐藏敏感字段 | 核对错误、任务完成比例 |
| 经过者不应引发频繁中断 | 朝向、持续性与可靠性判断 | 无风险误遮挡、切换次数 |
| 返回同一字段时继续保护 | 内容身份与历史关联 | 错误重置、重复展示辨认 |
| 保护后还能完成任务 | 历史恢复与主动查看 | 查看次数、完成时间、用户反馈 |
| 摄像头使用透明可控 | 主动启用、状态提示、暂停退出 | 接受程度、实际暂停与退出行为 |

最终报告保留有调研依据的需求，并说明需求如何改变设计。需求调查人数与技术实验人数分别统计。

### 4.3 调研成果

- 场景需求分析报告及匿名记录。
- 用户任务流程图和中断节点。
- 核心需求、次要需求与本期范围。
- 设计决策来源表及版本变化。

## 5. 场景创新与差异化

### 5.1 创新表达

候选创新为：**面向敏感字段反复核对的任务，将环境感知、内容历史和可控恢复接入同一流程，在保护效果与任务连续性之间作出决策。**

“图书馆＋摄像头遮挡”本身不足以建立场景新颖性。需要展示真实任务中的未满足需求，以及本方案相对现有处理方式的实际改进。

### 5.2 传统方式与本方案

| 方式 | 机制 | 需要比较的问题 |
|---|---|---|
| 手动最小化或切换 | 使用者发现风险后中断展示 | 操作成本与反应时机 |
| 始终隐藏字段 | 维持保护，主动展示 | 任务可完成性与查看成本 |
| 第二张脸即遮挡 | 以人脸出现作为触发 | 经过者误遮挡 |
| 瞬时风险保护 | 风险解除后恢复 | 重复观察和反复展示 |
| 固定累计与恢复 | 简单历史控制 | 是否已足以满足任务 |
| 本方案 | 内容关联、校验后的累计与历史恢复 | 相近任务成本下的独立收益 |

### 5.3 三项候选贡献

| 贡献 | 场景作用 | 验证方式 |
|---|---|---|
| 内容身份关联 | 字段移动和重现时延续保护历史 | 展示实例计时对照与消融 |
| 暴露统计校验 | 为短片段和重复展示选择合理代理量 | 受控辨认与独立测试 |
| 历史恢复与可控查看 | 支持安全状态变化后的任务继续 | 固定恢复对照、任务成本与辨认 |

预训练感知模型属于复用基础，字段 ID 与界面属于实现基础。自研机制、复用模块和实验发现分开说明。已有 PrivacyScout 研究观察者特征与风险，Eye-Shield 研究实时屏幕保护与可用性；以论文和产品检索进一步限定创新主张。[PrivacyScout](https://petsymposium.org/popets/2022/popets-2022-0090.pdf)、[Eye-Shield](https://www.usenix.org/conference/usenixsecurity23/presentation/tang)

## 6. 场景解决方案与操作流程

### 6.1 方案组成

| 组成 | 场景中的作用 |
|---|---|
| 后台保护原型 | 用户主动开启后持续感知，提供托盘入口 |
| 机主状态管理 | 先由用户选中并跟踪；闭环稳定后增加主动登记与持久验证 |
| 敏感材料任务界面 | 呈现可滚动、多页、带敏感字段的材料 |
| 内容保护控制器 | 关联内容历史，判断保护和恢复 |
| 局部隐藏组件 | 保留任务布局，隐藏敏感正文 |
| 用户确认交互 | 支持按住或限时查看、紧急隐藏、暂停 |
| 实验与记录模块 | 记录动作、作答、任务与性能 |

原型首先适配 Windows 与自有任务界面，支持范围以实际测试为准。它是完整场景验证的技术载体。

### 6.2 场景实施流程

1. 使用者启动原型，了解摄像头使用与支持范围。
2. 主动启用并手动指定机主，完成朝向基准检查；持久验证扩展通过后可提示匹配结果，身份不确定时重新确认。
3. 打开结构化材料，确认敏感字段与等级。
4. 继续查看和核对，主控制面板可收至托盘。
5. 周围人员出现时，结合朝向、持续情况和可靠性判断风险。
6. 按字段等级与历史执行局部隐藏，非敏感内容保持可见。
7. 风险解除或用户需要查看时，按恢复规则继续任务。
8. 完成任务后释放摄像头；实验记录与材料分别管理。

### 6.3 内容保护方式

普通屏幕采用不透明字段隐藏或占位块，本人也会受到遮挡。通过局部范围、恢复和主动查看降低任务干扰。模糊、半透明和调暗只作为提示或后续研究，不直接计为有效隐藏。

本期主要保护自有任务界面中的字段。第三方软件可在后续增加用户框选区域，但固定屏幕坐标不等于消息身份，滚动和窗口移动后需重新定位。该扩展不作为本期场景效果的前提。

按角度改变同一区域的可读性属于显示硬件或单独图像处理研究，本期使用风险触发后的局部隐藏。[三星显示结构说明](https://www.samsung.com/ae/support/mobile-devices/when-i-turn-on-privacy-display-the-ppi-clarity-and-brightness-decrease-on-my-galaxy-s26-ultra-why-does-this-happen/)

## 7. 技术架构与实现手段

```text
场景需求与任务脚本                 普通摄像头
        ↓                             ↓
结构化材料与敏感字段             采集、多人关键点、短期跟踪
        ↓                             ↓
内容 ID、版本与可见区域          手动机主选择 / 可选身份验证
        ↓                             ↓
内容展示历史                    非机主人员的风险与可靠性
        └─────────────┬───────────────┘
                      ↓
             风险与内容历史控制器
                      ↓
            局部隐藏、恢复与主动查看
                      ↓
              核对 / 填写 / 任务完成
                      ↓
         事件日志、辨认结果、任务与用户反馈
```

### 7.1 摄像头采集与后台运行

Python 与 OpenCV 负责摄像头采集，PySide6 提供任务界面和托盘。采集与推理放在工作线程，主线程负责界面，结果携带时间戳并限制排队长度。过期结果不得用于当前恢复决策。

托盘显示运行、暂停、保护中和输入异常。显式退出释放摄像头和线程；关闭主面板时可继续托盘运行。离线演示前完成模型与依赖准备。[Qt 托盘](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QSystemTrayIcon.html)、[Qt 线程](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QThread.html)

### 7.2 人员感知与风险线索

使用 MediaPipe 提取多人面部关键点及可用变换信息，设置多人数量并实测。第一阶段由用户主动选择机主，独立的跨帧关联模块维持 track_id；frame face 序号不作为身份。机主丢失、交叉遮挡或关联不确定时，进入保护并请求确认。[MediaPipe 官方文档](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/python)

| 特征 | 作用 | 解释范围 |
|---|---|---|
| 头部朝向 | 判断可能朝向屏幕 | 粗粒度线索，区别于眼动 |
| 图像位置 | 判断人员出现位置 | 受摄像头布局影响 |
| 人脸相对尺寸 | 辅助判断靠近变化 | 不直接等于绝对距离 |
| 持续性 | 区分短暂经过和持续出现 | 时长配置由开发实验确定 |
| 图像质量、结果时效 | 决定观测是否可用 | 失效时进入回退 |

首版采用可解释规则计算风险，多人使用最大单人分数作为基线。规则分数不解释为真实泄露概率。AI 的场景价值通过与第二张脸基线比较体现，无需为形式增加大模型。

身份层与风险层分开：已确认的机主从旁观者风险列表排除，其余人员按可见、朝向和持续性分析。“非机主”包括熟人，身份未知也不表示恶意；身份不确定不能自动获得机主豁免。机主离开或关联失效时优先保护。

### 7.3 内容身份与结构化材料

采用项目定义的 JSON 材料格式，包含字段 ID、显示文本、版本、敏感等级与页面位置。任务界面直接提供当前可见状态。

| 字段 | 含义 |
|---|---|
| content_entity_id | 同一敏感字段的稳定身份 |
| content_version_id | 字段内容改变后的版本 |
| display_instance_id | 本次展示实例 |
| region_bbox / visible | 当前位置与实际可见性 |
| sensitivity | 用户确认的保护等级 |
| exposure_state | 可见时长、片段与累计历史 |
| protection_state | 隐藏、等待或短时展示状态 |

滚动或切换页面不重置同一字段。部分字段修改只更新对应版本，其他字段保留历史。人员跟踪编号变化不清除内容记录。

### 7.4 暴露代理量与校验

记录总风险可见时长、最长连续片段、片段数、重复展示次数和风险加权累计量。候选模型为：

\[
E_c(t+\Delta t)=E_c(t)+q_t v_{c,t}(1-m_{c,t})\Delta t
\]

其中 \(q_t\) 为风险分数，\(v_{c,t}\) 为可见状态，\(m_{c,t}\) 为已经生效的隐藏状态，实际间隔由单调时钟计算。

内容不可见或有效隐藏时暂停新增；转头与暂时离开不清零。观测未知区间记录为未知并执行回退。受控辨认数据用于比较候选量；若简单总时长已经足够，采用简单模型并调整贡献表述。

### 7.5 隐藏、恢复与查看

自有任务界面将原字段替换为不透明占位块，保留布局和导航。高敏感字段先确定保护状态再绘制，避免初次展示空档。日志分别记录命令和实际界面生效时间。

| 条件 | 动作 |
|---|---|
| 高敏感字段 | 默认隐藏，明确操作后按策略限时展示 |
| 高敏感字段出现明显风险 | 立即隐藏，不等待累计 |
| 中敏感字段风险或历史达到条件 | 局部隐藏，保留历史 |
| 风险可靠解除且历史较低 | 等待后恢复 |
| 机主离开或身份关联不确定 | 保护已管理字段，等待机主明确确认 |
| 历史较高 | 保持隐藏，通过主动查看继续任务 |
| 输入过期、质量不足或使用者丢失 | 进入异常保护并提示 |
| 用户强制解除或暂停 | 明确显示状态，记录操作，不清除历史 |

状态机至少包含校准、正常、风险确认、保护、恢复等待、短时展示、输入异常和暂停。明确风险或输入异常可提前终止限时展示；强制解除属于单独用户操作。

### 7.6 日志与隐私

默认记录匿名时间戳、内容代号、风险、可靠性、配置、保护动作和任务结果，不保存原始人脸视频或敏感原文。受控实验录制单独取得同意，明确用途、保存期限与删除方式。

未检测到额外人脸只表示当前观测结果；摄像头盲区通过现场测试说明。已经被观察的信息无法通过后续隐藏收回。原型失效时提示状态，并提供人工隐藏或停止展示。

## 8. 技术选型、资源与可行性

机主身份验证作为第二阶段增强模块，核心保护闭环不依赖它才能启动。具体实现与接续安排见第 24 节。

| 技术或资源 | 用途 | 选择理由 |
|---|---|---|
| Python、虚拟环境 | 统一实现与复现 | 易于集成感知、控制与实验 |
| OpenCV、MediaPipe | 摄像头与预训练视觉基础 | 普通摄像头可开展开发验证 |
| YuNet、SFace（第二阶段） | 人脸对齐、机主特征与验证 | 使用 OpenCV 官方流程，独立测试后接入 |
| PySide6 | 托盘、任务界面与字段隐藏 | 可直接控制字段显示和交互 |
| NumPy、pandas、Matplotlib | 数据整理、统计与图表 | 对照和证据可复核 |
| JSON、CSV | 材料、配置与匿名日志 | 结构明确、便于版本管理 |
| Git、录屏工具 | 实施记录与演示 | 保留过程和成果一致性 |
| 可运行包或清晰环境指南 | 测试与部署 | 便于复核原型和现场备用 |

在现有电脑上实测采集分辨率、推理频率、延迟与资源占用，锁定通过验证的版本。无可用摄像头时，视频回放可验证控制，但真实场景测试仍需可用摄像头。

场景实施还需参与者、获准测试场地和排期。人员及场地未落实时在计划中标记待落实，不写成已有合作。

本期优先完成核心任务和证据；OCR、任意文件解析、跨应用适配、手机端与光学仿真不进入首期必做范围。

## 10. 测试与验证设计

### 10.1 功能与可靠性

测试开启、托盘、暂停、退出、摄像头失效、结果过期、使用者丢失、字段隐藏、滚动、版本变化和风险再次出现。重点检查部分更新、重新展示和恢复期间的状态。

测试报告记录输入、预期、实际、失败原因、修复版本及回归结果。统计端到端延迟分布、资源占用与长时间运行情况。

### 10.2 暴露量与辨认实验

采用连续、间歇、滚动重现和内容更新条件，匹配总展示时长与内容难度。参与者展示后作答，记录字符比例、关键词与完整内容辨认。

开发试次选择模型与阈值；正式测试使用新内容，条件允许时留出参与者。队员数据用于预实验，独立用户验证争取约 15—25 名作为工作量目标，实际人数依据资源和预实验确定。分别报告人数、试次数和逐人结果。

### 10.3 真实场景任务测试

让使用者完成统一的虚构材料核对任务，观察者按脚本在获准测试场地执行经过、持续观察和多次短观察。记录观察位置、角度、光照、屏幕与字体设置以及摄像头覆盖。

相同条件下比较手动保护、第二张脸、展示实例累计、内容关联固定策略和完整策略。随机或平衡条件顺序，避免反复使用同一答案造成学习优势。受控展示与真实摄像头端到端结果分别报告。

### 10.4 公平比较与消融

| 对照或消融 | 检验问题 |
|---|---|
| 始终隐藏 | 保护边界与任务不可完成情况 |
| 手动隐藏或切换 | 对当前做法的任务成本改善 |
| 第二张脸保护 | AI 风险线索是否减少误遮挡 |
| 展示实例累计 | 内容关联是否必要 |
| 内容关联＋固定累计＋固定恢复 | 复杂策略是否超越简单完整实现 |
| 移除内容历史 | 历史是否有独立作用 |
| 固定恢复替代历史恢复 | 收益是否只是遮挡更久 |
| 移除可靠性回退 | 输入失效时的错误恢复 |

自动策略共用感知输出与内容条件；仅开发数据调参，正式测试前冻结。比较相近遮挡或任务成本下的辨认结果，同时报告多阈值折中关系。

### 10.5 指标与解释

| 类别 | 指标 | 解释 |
|---|---|---|
| 保护效果 | 字符、关键词、完整辨认率 | 观察者实际作答结果 |
| 任务效果 | 完成时间、错误、未完成比例 | 使用者是否能正常完成任务 |
| 操作负担 | 查看、切换、强制解除次数 | 方案是否增加额外操作 |
| 感知控制 | 误遮挡、未保护时长、触发延迟 | 风险识别与执行表现 |
| 状态管理 | 错误重置、错误恢复 | 历史机制正确性 |
| 系统性能 | 延迟分布、CPU、内存、稳定性 | 场景运行条件 |
| 用户反馈 | 接受、理解、继续使用意愿 | 与实际行为交叉解释 |

主要结论围绕同等任务质量和相近成本下的保护收益。所有数值由实际测试产生，报告差异与不确定性；未完成任务不从分析中删除。

## 12. 实施条件、推广与隐私

### 12.1 实施条件

需要支持环境的电脑、可用摄像头、明确的材料接口、目标用户及获准测试的场地。现场先确认旁观位置是否同时满足可读与可检测，再确定适用范围。

初期由用户主动运行。摄像头状态持续可见，原型可暂停、退出和删除记录。高敏感内容默认隐藏，输入失效执行回退；摄像头盲区保留人工保护手段。

### 12.2 推广路径

| 阶段 | 工作 | 进入下一阶段的条件 |
|---|---|---|
| 受控验证 | 虚构材料、脚本与原型 | 核心功能稳定，结果可复核 |
| 目标用户试用 | 实际使用习惯下执行材料任务 | 任务可完成，用户反馈可接受 |
| 获授权的小规模场景实施 | 明确地点、负责人和维护方式 | 效果与隐私处理通过现场检查 |
| 接入扩展 | 对接具体材料工具或应用 | 内容身份、位置与异常均可验证 |

推广资源、维护成本与兼容性按实际调研记录。社会价值重点评价低硬件门槛下的任务隐私改善，不用未经调研的市场规模代替应用证据。

### 12.3 隐私与失败条件

参与者知情、自愿、可退出。默认本地处理且不保留原始视频；实验录像单独授权。日志使用匿名代号，公开数据移除可识别信息。第三方算法、模型和库核实授权并标注来源。

保护范围是当前显示的敏感内容，遮挡同时影响本人。摄像头盲区、头部朝向误判、输入失效和主动解除分别报告；已观察的信息不会被后续遮挡消除。录屏、远程桌面和操作系统安全不纳入本期效果结论。

### 16.3 一台电脑的推荐安排

| 使用时段 | 主使用者 | 主要内容 |

| 每日第一个连续约 2 小时 | A | 感知和控制开发、性能测量 |

这是可调整的排班建议，不预设团队已经承诺相应工时。实验日优先让出连续机时给参与者；开发者在场观察问题，正式试次期间不现场调参。

## 20. 技术实现顺序与接口验收

### 20.1 模块必须按此顺序验证

| 顺序 | 技术能力 | 具体实现步骤 | 必须观察到的结果 |
|---:|---|---|---|
| 1 | 摄像头输入 | 打开设备、读帧、失败上报、关闭释放 | 连续画面与正确退出 |
| 2 | 多人感知 | 转为模型输入颜色格式、设置多人、关联时间戳 | 两人分别输出，不依赖返回排序作为身份 |
| 3 | 使用者指定 | 用户选择、短期匹配、丢失提示 | 排除主要使用者且不把编号变换当新内容 |
| 4 | 粗粒度风险 | 朝向校准、持续性、聚合、可靠性 | 同输入能输出分数与原因 |
| 5 | 字段保护 | 字段映射到组件、替换正文、保持布局 | 指定字段隐藏，其他内容可用 |
| 6 | 内容关联 | 实体/版本/实例分离，保存和读取历史 | 位置变化不重置，内容变化按字段更新 |
| 7 | 累计记录 | 单调时钟、可见性、执行状态确认 | 隐藏或不可见暂停新增 |
| 8 | 恢复控制 | 迟滞、等待、限时查看、异常中断 | 状态转换与事件原因对应 |
| 9 | 后台运行 | 工作线程、托盘、暂停、退出、结果过期 | 主界面收起后工作，退出释放 |
| 10 | 实验工具 | 试次开始、策略配置、答案、任务终止 | 一个试次的全链条可复核 |

### 20.2 接口最低字段

| 接口 | 生产者 → 使用者 | 最低字段 |
|---|---|---|
| 感知结果 | A → 控制器/B | 帧时间、结果时间、人员临时编号、使用者标记、位置、朝向、可靠性、输入状态 |
| 内容状态 | B → 控制器/A | 实体、版本、实例、等级、位置、可见状态、实际隐藏状态 |
| 控制输出 | A → B | 内容键、动作、原因、命令时间、累计状态、配置版本 |
| 执行确认 | B → A/日志 | 内容键、界面已更新状态、更新时间、执行异常 |
| 试次上下文 | C 的计划/B 的工具 → 日志 | 参与者代号、角色、试次、条件、材料代号、策略、版本、随机种子 |
| 作答与任务结果 | 作答工具 → C | 试次、答案结果、开始/结束、完成/超时/退出、错误与操作次数 |

GUI 更新事件只确认组件状态已更新，不等于已测量显示面板发光时刻。端到端延迟在报告中说明测量端点，不能把推理耗时直接当作保护生效延迟。

### 20.3 简化但保留完整任务

第一版可以先支持一种 JSON 材料、单台电脑和一个任务窗口。用户通过字段配置人工确认敏感等级，这属于首版设计。自动识别任意敏感文本、任意第三方消息、精确眼动和绝对距离不作为前置依赖。

如果模型运行不稳定，优先修输入与可靠性；如果累计模型无优势，选择简单量；如果应用级遮挡还未可靠，先不做外部桌面覆盖。

## 21. 实验当天的详细操作流程

### 21.1 测试前准备

1. C 核对同意、参与者代号、角色与日程；解释可随时退出。
2. A 记录设备和环境，启动冻结版本与正式配置，确认摄像头覆盖。
3. B 检查材料身份、布局、作答入口和日志路径，清理上次试次状态。
4. 固定屏幕、字体、观察位置与光照记录方式，准备不同条件的新材料。
5. 用不进入正式分析的练习内容，让参与者理解查看和作答。
6. C 核对条件顺序表；观察者不得提前看到答案。

### 21.2 每个真实任务试次

| 步骤 | 操作人 | 操作 | 记录 |
|---|---|---|---|
| 1 | C | 宣布任务与条件，确认试次编号 | 条件、材料和角色 |
| 2 | A | 确认策略和人员指定 | 配置、版本、输入状态 |
| 3 | 使用者 | 点击开始，执行核对或填写 | 起始时刻、滚动和查看事件 |
| 4 | 观察者 | 按脚本经过、持续或反复观察 | 观察片段起止和位置 |
| 5 | 使用者 | 完成任务或达到预设终止条件 | 结束、答案、错误、未完成 |
| 6 | 观察者 | 独立输入看到的内容 | 字符与关键词作答 |
| 7 | C、B | 保存并核对试次完整性，收集简短反馈 | 缺失、故障、解除与反馈 |

观察标签由主持记录或经授权录像复核，模型自身的风险分数不能同时当作真实观察标签。若角色互换，每人每角色分别记录，材料不重复泄露答案。

### 21.3 受控辨认试次

使用固定呈现时间线隔离感知误差，比较连续与多片段展示等条件。内容展示后立即作答，匹配总时长和难度。它验证代理量与辨认关系，不直接证明真实摄像头系统效果。

### 21.4 首期数量安排

先完成队员预演，随后根据可用参与者和机时安排独立用户。优先确保每个主要策略在可比条件下有真实试次，再增加额外观察条件。不要为凑所有策略让单人完成过多试次，避免疲劳和学习。

预实验可以按每人约 15—20 分钟预约作为起点，实际时长由练习测得；正式实验按测得时长安排。15—25 人是后续独立验证招募目标，不是首期必须达到的赛事人数。

### 21.5 数据复核与分析步骤

1. 原始事件只追加保存，清洗生成新文件并记录规则。
2. 核对参与者、试次、配置、材料与答案能关联，检查重复和时间异常。
3. 未完成、退出和故障分别标记；按事先规则处理并报告数量。
4. 按实际隐藏状态和外部观察标签计算未保护时长。
5. 根据作答和任务结果计算辨认、时间、错误和操作次数。
6. 先按参与者汇总，再比较策略，不把同一人的多试次当作大量独立用户。
7. 绘制逐人结果、策略对比、历史时间线、效果—成本曲线和性能图。
8. 检查优势是否来自更多遮挡、更简单材料或更有利的观察位置。

### 24.2 两阶段路线

**第一阶段：手动机主与保护闭环。**

```text
已完成：摄像头 → MediaPipe 多脸关键点 → 显示与日志
                               ↓
新增：跨帧跟踪 → 点击选中机主 → 机主状态与非机主列表
                               ↓
                 朝向、持续性、位置与观测可靠性
                               ↓
                 内容历史、字段隐藏与保护恢复
```

**第二阶段：持久机主验证。**

```text
用户主动登记 → 选中本人 → 合格样本 → 本地 SFace 特征模板
                                              ↓
实时图像 → YuNet 检测与对齐 → SFace 特征 → 与模板比对
                                              ↓
                              匹配 / 非机主 / 身份不确定
                                              ↓
                   与 MediaPipe 目标、track_id 一对一关联
                                              ↓
                   更新机主状态，复用第一阶段保护控制器
```

机主在场时仍分析其他人员；身份验证不能单独解除高敏感保护。首期优先完成第一阶段，持久验证在闭环稳定后启动。

### 24.3 模型与算法职责

| 模块 | 技术 | 输出 |
|---|---|---|
| 感知底座 | OpenCV＋已有 MediaPipe 模型 | 图像、多脸关键点、区域 |
| 短期关联 | 区域重叠、中心移动与尺寸门限 | track_id、关联质量 |
| 会话机主 | 用户点击、角色绑定与丢失处理 | owner_track_id、机主状态 |
| 朝向与风险 | 变换信息或关键点几何、可解释规则 | 粗粒度朝向、风险原因、可靠性 |
| 身份检测与对齐 | 第二阶段 YuNet、OpenCV 对齐 | 对齐人脸 |
| 持久身份 | 第二阶段 SFace、特征匹配与多帧确认 | 相似度、身份状态与质量 |
| 保护控制 | 内容实体、版本、累计和状态机 | 隐藏、等待、主动查看与恢复 |

YuNet 与 SFace 按 OpenCV 官方检测、对齐、特征和匹配流程接入；MediaPipe 继续提供姿态基础。不要把全部 MediaPipe 关键点直接当作 SFace 官方对齐输入。[官方流程](https://docs.opencv.org/4.x/d0/dd4/tutorial_dnn_face.html)

这些模型使用预训练权重，首版不训练新网络。新增模型是复用工程能力，场景贡献仍以需求适配和实际效果证明。

登记只保存本人确认的模板，默认不保存照片，不建立旁观者身份库。特征仍按敏感数据本地限制访问并保护存储，不写入普通事件日志。登记更新不得由运行过程自动改写。

样本归一化、模板聚合与相似度方法明确记录；例如多样本形成代表模板后，在开发数据检查稳定性。阈值、质量门限和连续确认时间由独立于正式测试的数据确定，不直接套用教程数字。

对照片或屏幕回放等误接受条件补测试。普通特征比对不作为活体认证或系统解锁；高敏感展示仍保留明确操作与即时风险控制。

### 24.6 身份与防护状态

| 身份状态 | 含义 | 防护处理 |
|---|---|---|
| MANUAL_CONFIRMED | 用户本会话选中且关联可靠 | 排除该目标，其余人员继续风险判断 |
| VERIFIED | 模板在质量和确认规则下匹配 | 更新机主状态，其余人员继续判断 |
| NON_OWNER | 合格比对未匹配模板 | 分析旁观风险，不解释为恶意 |
| UNKNOWN | 未登记、质量不足、歧义或关联失效 | 不授予机主豁免，维持必要保护 |
| OWNER_ABSENT | 已确认机主不在可靠观测中 | 保护已管理内容，返回按流程确认 |

每个会话最多确认一个机主目标。多个候选同时像机主时进入未知。非机主包含熟人，“陌生面孔”在产品中表述为未匹配登记机主。

控制器同时接收机主状态、非机主风险、可靠性、内容历史和用户操作。机主匹配只解决角色区分，不代表屏幕无人观察。

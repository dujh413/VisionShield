# 机主独处错误遮蔽修复（2026-10-06）

摄像头已显示“机主独处且已确认”，但桌面仍维持模糊或深色遮蔽。此次修复状态联动，不更换人脸模型、身份阈值或机主模板。

## 原因

1. 控制器将 OCR 的 `view.full` 合并到保护风险输入。首次文字分析、空 OCR 结果和大面积动态内容都会令该值为真，导致身份已经安全时仍不断清空恢复计时。
2. 摄像头使用仅保留最新状态的有界队列，而恢复状态要求序号逐帧相邻。正常淘汰旧安全帧后出现跳号，会反复重启一秒的恢复确认。

## 修复

普通内容待分析只决定已有风险时遮蔽哪些区域，不再制造身份风险。摄像头、OCR、桌面采集真实故障仍触发保护；已有 OCR 结果十秒过期的处理保持有效，未来或非有限的采集时间也不能恢复。首次 OCR 加载超过原有三十秒启动宽限仍按异常保护。

摄像头在候选人脸和旁人保持处理后，累计记录所有身份保护风险，包括旁人、候选人脸、无人脸和机主未确认。最新安全状态仍携带最近风险序号和观察时间；接收端验证字段完整性、类型、范围和历史单调性。仅有完整且未出现新风险的历史，才允许安全帧跨正常队列跳号继续确认。

遗漏的新风险会清空恢复计时。重复同一帧不累计安全时长，倒序、过期、缺失记录、会话切换和超过一点五秒的观察中断仍重新确认。未提供累计风险记录的旧身份接口保持严格跳号处理。持续收到有效安全观察约一秒后恢复；恢复确认期间显示相应说明。

敏感内容和未知区域的坐标校验保持有效；真正存在旁人风险时仍使用这些结果。所有遮蔽仍受应用/选区范围约束，范围失配不扩大到范围外。

- 桌面模块 398 项、摄像头模块 68 项回归全部通过，共 466 项；包括实际 GPU 模糊回归。
- 覆盖模糊和深色模式下机主安全时空 OCR、首次加载、大面积画面变化和最新帧跳号后恢复。
- 覆盖被淘汰的候选人脸/未确认风险、旁人事件、重复/倒序/陈旧观察、无效历史、OCR 过期和采集异常仍保护。

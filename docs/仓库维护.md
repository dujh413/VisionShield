# 仓库维护

源码与已发行软件公开可读，访客没有直接修改权限。所有者维护main；协作者通过分支与PR交付，由所有者审核。主分支禁止强推和删除，版本标签仅由所有者创建和维护。规则配置保留在 `.github/rulesets`，实际规则需在GitHub启用。

保留软件运行源码、依赖、模型准备、回归测试、诊断工具、构建、验收、许可及当前使用文档。个人环境、模型缓存、面部模板、真实画面、聊天、凭据、设备日志和本地工作材料不得进入Git。回归测试用于维护，不因不随EXE运行而删除。

每次修改先获取远端更新、检查本地状态，再运行相关验证并审查暂存内容。不要用git add -f绕过忽略规则，不覆盖组员工作。修改源码后需要重新构建并发布新版本才能更新下载的软件。

公开前历史迁移的原始备份只保存在本机及私有归档仓库，不作为公开发布内容。历史迁移后协作者重新克隆，不把旧克隆的提交或标签重新推回公开仓库。

提交作者使用GitHub匿名邮箱，第三方许可署名保留。发现凭据应先撤销或轮换，再协调清理；日常维护不自动改写历史。构建清理只适用于[受限构建产物](构建验收与清理.md)。

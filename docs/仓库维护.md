# 仓库维护

仓库及Release保持私有，仅所有者和受邀成员可访问。所有者维护main；队友通过任务分支和PR交付，由所有者审核。每次修改先检查远端更新及本地未提交内容，不强推、不覆盖组员改动、不擅自合并PR。邀请成员不会因仓库整理而改变。

仓库保留运行源码、依赖、公共模型准备脚本、回归测试、现用诊断和性能工具、构建与验收、第三方许可、协作指南和当前操作说明。文件是否保留按实际引用和维护用途判断，不按日期批量删除。规则定义保留在`.github/rulesets`，实际保护效果还受GitHub账号套餐及已启用规则影响。


日常操作为检查更新、修改、运行相关测试、`git diff --check`、审查暂存路径和内容，再提交、推送。推荐显式添加文件，避免`git add -f`绕过忽略规则。源码变更需要重新构建和发行才能进入下载版；发布时同样检查软件包的私人文件和对应许可。

修改或删除当前文件不会清除Git历史。隐私检查要分别检查当前分支、可达历史、Release及附件；Git提交作者信息与第三方许可署名也会留在历史中。发现真实凭据时先撤销或轮换，再评估历史清除；不自动强推改写历史或删除其他成员的分支。

当前软件验收入口见[Windows云端测试](Windows云端测试.md)。构建产物按[清理规则](构建验收与清理.md)处理，个人数据、模型、源码和本机环境不在自动清理范围。

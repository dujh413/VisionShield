# GPU OCR 启用与验证（2026-10-05）

源代码基线为 main `8a46980f6324a12df4755ea2cacb90bbbf13d791`。本次启用现有 DirectML OCR，新增环境启用脚本与真实 GPU 自检，没有修改检测分辨率、模型、敏感规则、坐标校验、OCR 调度、四行 GPU 批次或模糊算法。

## 已启用的环境

本机工作区源码的桌面模块 `.venv` 已准备并启用 ONNX Runtime DirectML 1.24.4；检测、识别优先会话均为 `DmlExecutionProvider`，选中 DXGI device_id=0：NVIDIA GeForce RTX 4060 Laptop GPU，专用显存枚举约 7956MiB。原 CPU 测试环境保留为 ORT 1.30.0，文件及 provider 没有被覆盖。

此前 `pip show` 同时显示 CPU onnxruntime 1.30.0 与 onnxruntime-directml 1.24.4 已安装，但实际导入版本为 1.30.0，只有 Azure/CPU provider。这两个发行包共享 `onnxruntime` 模块目录；安装记录不能证明哪一套运行时文件最后生效。修复是在应用虚拟环境最后安装已固定的 DirectML 运行时，再用实际会话与算子跟踪确认。

requirements-extra.txt 已移除显式 CPU 1.30.0 pin。RapidOCR 的依赖仍可能拉入 CPU 发行包，因此更新依赖之后应运行 Enable-GpuOcr.ps1，不能只看 requirements 的顺序。脚本拒绝系统 Python；正确的 1.24.4/DML 环境不重复下载安装，但仍进行真实 GPU 自检。`-Repair` 可强制重装运行时，操作仅针对选定虚拟环境。

## 实际执行与回归

- 严格 GPU 自检通过：检测和识别会话首选 DirectML。ORT profiling 中检测有 1224 个 DirectML 算子执行事件、识别有 1705 个；识别同时存在 60 个 CPU 执行事件，不能称全部算子都在 GPU。计数含固定桶预热，不是不同算子的数量。
- 虚构中文、手机号、验证码、邮箱识别正确；敏感规则返回对应类别，输出只包含设备、provider、数量与通过状态，临时 profiling 文件结束后自动删除，不保留识别原文或图像。
- 独立 GPU OCR 子进程快速提交 61 帧，只传输、处理第1与第61帧，分别为 full 与 partial。实际检测与识别均首选 DirectML，最新验证码正确，关闭后进程退出。
- GPU 应用环境中 225 项桌面与 9 项身份回归全部通过，共234项，无跳过。Windows PowerShell 5 启用脚本实跑通过；再次运行不下载已正确的运行时；系统 Python 在安装前被拒绝。Python/PowerShell语法与 Git 差异检查通过。

DirectML 的设备编号按 DXGI 枚举顺序，不等同于随意选择任务管理器编号。现有 gpu_adapter.py 优先选本机 NVIDIA 显卡；应以自检输出的适配器和实际执行结果为准。配置要求见[ONNX Runtime 官方 DirectML 文档](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html)。

## 使用与复现

先按项目说明准备桌面 `.venv`、依赖与公开本地模型，在仓库根目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Enable-GpuOcr.ps1
```

成功后会输出实际显卡、检测/识别provider和 `passed: true`。该步骤不读取桌面或摄像头；只通过虚构文本验证GPU。已有正确环境无需重装；若依赖更新覆盖了共享模块，会重新安装固定DirectML。可用 `-Python` 指定另一个已准备好的虚拟环境，或用 `-Repair` 强制修复。

源码启动的 Launch.ps1/启动视界盾.cmd 默认使用桌面模块 `.venv`，因此该源码目录后续启用防护会使用已验证的GPU OCR；无需增加前端GPU开关。单独重复验证：

```powershell
.\视界盾桌面防护\.venv\Scripts\python.exe .\视界盾桌面防护\gpu_ocr_check.py
```

复测两种模式（先创建 records 目录，在桌面模块运行）：

```powershell
.\.venv\Scripts\python.exe benchmark_effect_latency.py --samples 30 --large-samples 10 --output records\gpu_effect_latency.json
```

该命令的输出留在本机忽略目录，不上传运行数据。环境、模型和临时 profiling 不同步到仓库。其他机器拉取源码后仍需在本机运行启用脚本；GitHub不保存Python环境。GPU预热会增加冷启动开销，该30帧统计剔除了模型初始化、首次整屏帧及3帧预热。生产无DirectML时仍按原逻辑回退CPU，GPU自检则明确失败，避免把回退误认为加速成功。

打包前应在实际构建Python环境运行同一GPU自检再执行 packaging/Build.ps1。本轮没有重新构建exe；已有便携包的内置运行时不会因源码环境更新而改变。此项只验证OCR部分，不代表整个摄像头/隐私防护流程已经在真实设备验收完成。

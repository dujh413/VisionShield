# 人脸检测后续改进记录

日期：2026-10-06。本文记录摄像头状态时序、弱候选保护与扫描调度的修复及验证结果。上轮身后模糊、遮挡旁人的持续实人检测尚未通过，本轮没有把合成样本当作实人验收。

## 本轮已经验证的改动

### 1. 状态使用帧的采集时刻

`LatestCameraFrame` 在采集线程成功读到一帧后记录本机单调时钟，只保留最新一帧。消费者取帧时同时取得该帧的时间；没有新帧时等待，不能把旧画面重复当作新观察。

`camera_worker.py` 将该时间作为 `observed_at` 传给检测、人物跟踪与身份状态判断，并附在输出状态中。处理完成时间只用于计算耗时。相机状态是否过期，也从 `observed_at` 判断，避免慢推理把一张旧画面包装成刚发生的安全观察。

新增测试覆盖主循环等待新帧的情况：即使等待期间时钟已推进，检测、身份判断和发布状态仍使用实际取得帧的采集时刻，不能使用等待之前的循环起始时间。

这里的采集时刻是“采集线程成功读取帧的时刻”，不是摄像头硬件曝光时间。尚未测量传感器曝光、设备缓冲、显示输出的完整延迟。

### 2. 丢弃旧状态时仍保留旁人检测事件

输出队列保持有界，处理端仍可以只取最新状态。新增加的 `StrangerJournal` 在检测链路实际产生旁人观察时，记录该观察的序号和采集时刻，并把最近一次事件标记带入后续状态：

```text
last_stranger_sequence
last_stranger_observed_at
```

这样即使中间“检测到旁人”的状态被最新安全状态替换，前端仍能发现尚未处理的旁人事件，触发保护与提醒。前端用单调推进的事件标记去重，不会在每次轮询时反复触发同一事件。

短暂风险保持发生在事件记录之后。保持期间没有新检测到旁人，就不更新事件的采集时刻。该标记记录最近一次实际检测事件，不是事件总数；“实际检测”也不等于经过人工核验的真实人物身份。

### 3. 重复安全帧不能推进自动恢复

`ProtectionState` 在产品路径接收观察的序号、采集时间及可选会话标识。默认恢复等待为1秒，安全持续时间由连续新观察的采集时刻计算。

| 观察情况 | 当前处理 |
|---|---|
| 同一份安全状态被界面重复轮询 | 保持当前状态，不累计新的安全时长 |
| 连续的新鲜安全观察 | 达到恢复等待时长后才恢复 |
| 观察序号跳跃 | 中断原安全计时，从新的连续观察重新确认 |
| 接口会话切换 | 不借用前一会话累计的安全时间 |
| 新风险出现 | 立即清除安全计时 |
| 观察缺失、过期、倒序、未来时间或无效字段 | 保持保护，不据此恢复 |

观察的默认有效期为1.5秒。已经恢复后重复读取仍在有效期内的同一安全观察，不会仅因重复读取而闪回保护；观察过期后会重新保护。缺帧只说明安全证据不连续，不直接生成“检测到陌生人”的提醒。

这些时序规则用于决定是否请求保护；实际遮罩仍遵循用户已经设置的范围，不扩大到其他应用或整屏。

### 4. 缺失或矛盾的状态不能声称安全

摄像头状态必须包含 `enrolled`、`protect_request`、`stranger_detected`，三个字段都必须是Python布尔值。字段缺失，或传入 `None`、数字、字符串等非布尔值时，接收端拒绝该状态并请求保护，不把它们自动转换成安全状态。

如果 `stranger_detected=True` 而 `protect_request=False`，仍按旁人风险请求保护，不能让错误的保护请求字段盖过旁人标记。

### 5. 有效弱候选等待确认时临时保护

`FaceScanner.current_unconfirmed_count` 只统计当前帧中通过有效性检查、但尚未通过跨帧确认的弱人脸候选。它不是全部低分检测框的数量，也不把已经消失、只留在短期几何缓存中的候选计入当前帧。

已登记机主且该计数大于0时，`camera_main` 将 `protect_request` 置为真，并输出 `candidate_pending=True`。状态说明为“候选人脸待确认，暂时保护”。该规则只增加保护请求，不改写机主或旁人身份判断，不把弱候选记录为 `StrangerJournal` 旁人事件，也不让弱候选刷新 `BystanderHold`。仅有待确认候选时，不生成“已经检测到旁人”的提醒。

弱候选通过确认后不再计入待确认数量；已确认的弱机主人脸不会仅因分数仍低而持续触发这一规则。后续是否恢复仍由正常身份结果和连续安全观察决定，不承诺确认一帧后立即恢复。

代价是误候选或机主检测分数由强变弱时可能短暂遮蔽；候选反复出现也可能反复触发保护。检测器完全没有产生候选时，该规则无法帮助发现身后的旁人，不能用它证明小脸漏检已经解决。

## 自动验证

最终自动回归共382项：桌面模块337项，335项通过、2项GPU专用条件测试跳过；摄像头模块45项全部通过。实际桌面联动另完成22个场景、100次Qt遮罩像素检查，选区外、其他应用、软件主界面的遮罩像素均为0。重复安全帧不解除保护、过期帧重新保护、连续新鲜安全帧恢复、窗口跟随、滑杆切换、选区失效及停止后资源释放均通过。联动使用真实mss采集、独立OCR进程和OpenCL模糊，人物风险为模拟状态；不等于真实双人检测验证，也没有测量显示器物理扫描输出。

新增回归包含宽ROI对比度增强独有的弱小脸发现、转为小ROI复检并跨帧确认的历史故障链。有效弱候选首次出现时计数、确认后清零、无效关键点不计入、已消失缓存不计入当前帧、强候选不因旧弱缓存持续保护，以及同一帧重复输入不能假装跨帧确认均已验证。

测试使用模拟时间、状态队列、检测结果与界面对象，没有打开真实摄像头，没有读取机主模板。

## 上轮 v4 仍未通过的范围

上轮实人结果见[指定范围与人脸检测修复报告](指定范围与人脸检测修复报告_20261005.md)。v4 在提示“旁人在身后”的75帧中，27帧检测到至少两张脸，存在4.38秒连续单脸输出，不能认定持续双人防窥通过。

该轮独处提示阶段共37帧，机主确认数为0；诊断显示清晰度门限拒绝了身份特征提取，不能据此认定个人模板损坏。最终代码已调整质量门禁与裁剪重复处理，但这些调整尚未重新完成真实双人验证。

人员进出时间没有独立逐帧标注，提示阶段与真实在场时间可能存在差异；模糊、遮挡和离开过程也会影响结果。因此，不能把上述帧数换算为精确召回率，也不能把离开提示阶段的全部双脸结果直接判为误检。

本轮时序修复防止旧安全状态、队列丢弃和重复轮询导致错误恢复，不能补回检测器没有找到的人脸，也没有证明4.38秒的漏检间隔已经消除。没有通过延长风险保持时间来替代小脸召回验证。

## 扫描调度及公开样本验证

公开静态人像合成测试属于算法回归：可比较人脸大小、模糊程度、扫描覆盖、重复检测和推理耗时，不能代替用户与旁人在摄像头前的真实双人验收，也不能证明机主模板匹配或真实动作过程可靠。

采用方案保留YuNet、SFace及原图/CLAHE局部复检。若整帧已清晰检出与当前focus相同的人脸（短边至少80像素、检测分数至少0.78，并核对框重叠和五点位置），跳过该ROI的原图重复推理，保留宽ROI的CLAHE探索，并轮转两块背景分区。未命中这个条件的小脸或弱候选仍执行原图与CLAHE复检、轮转一块背景分区。清晰背景人脸也可命中该条件；检测分数不代表已经确认机主身份。

保留宽ROI的理由经过反例验证：一个40像素、低对比度且模糊的小脸只有宽ROI的CLAHE能发现。直接取消focus、纯1.5倍全画面、原图/CLAHE全画面交替均使该样本出现退步，因此没有采用这些替换方案。有效弱候选仍可作为复检入口，无效关键点不计入待确认保护。

测试机为Windows 11、AMD Ryzen 7 7745HX、OpenCV 4.10.0；检测使用单CPU线程、1280×720合成画面，不加载SFace或个人模板。素材是两张公开人像：[scikit-image astronaut来源说明](https://scikit-image.org/docs/0.25.x/api/skimage.data.html#skimage.data.astronaut)及[Google Coral图像版权记录](https://github.com/google-coral/test_data/blob/104342d2d3480b3e66203073dac24f4e2dbb4c41/COPYRIGHT)。按空间框一一匹配，额外检测框单独计数；不是只检查人脸总数。

最终主要矩阵为27个场景、405帧。23个双人/多人场景中，目标旁人的276帧均匹配；129帧空图/单人及旁人出现前基线没有额外人脸。整轮检测耗时中位180.9ms、P95 247.6ms、最大548.6ms。案例结束时检测进程RSS中位112.0MiB、最大114.4MiB；这是检测进程的采样值，不是整套软件或内存峰值。

另测6个难例、90帧，并在同机单独运行旧提交作为对照：

| 合成场景 | 旧版目标匹配/首次确认 | 最终版目标匹配/首次确认 |
|---|---|---|
| 20像素清晰小脸，左侧 | 10/12；567ms | 12/12；240ms |
| 40像素低对比度、较轻模糊 | 11/12；380ms | 12/12；239ms |
| 40像素低对比度、较重模糊、分区附近 | 11/12；418ms | 11/12；422ms |
| 60像素低对比度、较重模糊 | 11/12；378ms | 11/12；424ms |

该对照没有消除所有漏帧，也没有证明所有场景都提速。清晰大脸时背景轮转由六帧覆盖变为三帧；增加第二块分区的成本可能超过省去的原图复检，实际毫秒间隔受负载影响。主要矩阵的背景重访仍有超过1秒的样本，不能宣传全背景500ms覆盖或硬实时响应。冷启动、SFace身份推理、摄像头曝光/设备缓存、IPC、实际显示输出的完整延迟未纳入这些检测数字。

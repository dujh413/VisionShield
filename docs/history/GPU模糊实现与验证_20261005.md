# GPU模糊实现与验证（2026-10-05）

基线为main `2aaa440dd63cb1ccf552858b62a9eaa6d478b21a`。数值模糊从NumPy CPU计算接入原生OpenCL GPU，保持盒式均匀滤波及前端半径语义。没有更换OCR模型、降低检测分辨率、改变敏感规则或缩小遮蔽范围。

## 使用与回退

在主界面输入整数如`8`、`16`、`32`，点击“启用防护”（开发控制面板为“启动 / 重试”）。输入的是物理屏幕像素半径r，核边长仍为2r+1，半径越大模糊越强。运行中修改输入须暂停、重新启用后生效。空输入不处理，其他字符深色遮挡，全角数字可用；半径0保留原像素，不创建GPU会话。

半径1–128自动使用驱动提供的OpenCL GPU，不需要新增Python GPU依赖。选择可用且支持编译的GPU，优先非统一内存设备，再考虑NVIDIA及显存容量。OpenCL模糊与DirectML OCR是各自的GPU链路，OCR启用脚本不负责安装显卡OpenCL驱动。无可用GPU、初始化/运行错误或超过128的半径，保留原CPU算法及完整半径，包括极大整数，不作截断。GPU故障在当前worker内禁用，避免每个区域重复初始化。

实现使用两个可复用、动态半径的整数求和核心，复制边缘。支持范围内总和不溢出uint32；奇数核面积无半整数取整歧义，避免不同显卡浮点精度影响像素。显式GPU设备、核心提交及事件起止计时完成后才记录`opencl-gpu`，没有OpenCV UMat的静默CPU回退。内核随Python源码打包，系统OpenCL.dll和显卡驱动不随软件分发。

## 稳定性与生命周期

- GPU会话在模糊worker线程第一次实际工作时创建，界面空闲、抹黑及关闭处理时不初始化GPU模糊。
- 每次裁剪图的GPU输入、中间和输出缓冲及事件都在完成后释放；常驻worker仅复用程序、核心和会话。暂停、模式切换、窗口关闭/隐藏时所属线程释放会话。
- 保留一个活动请求、一个可替换待处理请求，取消代次和最新区域精确像素校验拒绝旧结果。处理独立裁剪范围，仍保留被排除窗口的透明空洞。
- 初始化、计算和等待期间先深色保护，完成后替换为模糊；无GPU退回CPU后仍按该流程处理。关闭超时或持续资源释放错误会报告并阻止误称暂停成功。

## 本机实测

硬件为i9-14900HX、RTX4060 Laptop GPU；Python3.12.14、NumPy2.3.5、PySide6 6.11.2、ORT DirectML1.24.4。生成2560×1600虚构画面，不采集真实桌面或摄像头。使用实际BlurWorker/BlurCache、ContentState、OCR子进程/IPC和Qt离屏绘制；GPU测试互不并行。下表为暖机中位 / P95，单位ms；小区域30次、大区域10次，各剔除3次预热。

| 半径8场景 | 前次CPU后台计算 | 本次GPU后台计算（含传输） | 本次最终Qt绘制完成 |
|---|---:|---:|---:|
| 6个敏感区域，面积4.40% | 18.32 / 23.63 | 6.22 / 7.27 | 23.76 / 24.69 |
| 140行合并2列，面积69.42% | 602.92 / 610.89 | 8.73 / 9.55 | 29.49 / 33.02 |
| 全屏 | 814.72 / 863.26 | 10.23 / 11.48 | 31.20 / 33.14 |

前次CPU列来自[模糊与深色遮挡延迟实测](模糊与深色遮挡延迟实测_20261005.md)，是历史设备配置测量，不是同时运行的单变量实验。小区域后台计算变快，但Qt最终完成仍受20ms轮询与缓存校验/图像转换影响，前次小区域最终Qt中位22.37ms，本次23.76ms，不能声称所有场景显示都更快。大面积最终Qt历史中位约628.84/833.08ms，本次约29.49/31.20ms。

本次半径16/32的小区域后台计算中位6.38/5.52ms，最终Qt中位24.04/22.88ms；半径在每次调用传入，同一会话改变半径无需重新编译。另做全屏GPU核心自检：半径8包括分配和双向传输中位9.88ms，两个实际GPU核心合计中位2.15ms；不能将2.15ms当作完整渲染时间。

首次会话创建约0.6–0.8秒。本次6区域、密集、全屏首个模糊最终Qt分别622/630/630ms，先深色保护约1.35/3.48/3.06ms。每次暂停后重新创建会话可能再次承担初始化时间；暖机表不包含这笔开销。实际冷启动还受驱动和负载影响。

包含GPU OCR的合成8行、6敏感区域流程，每种模式30帧、3帧预热，保留全部8行及验证码、手机号、邮件识别，所有模糊完成帧实际后端为RTX4060 OpenCL，无CPU回退：

| 流程 | 中位 / P95 / 最大（ms） |
|---|---:|
| 帧到确认文字及最终深色遮挡 | 270.28 / 293.14 / 293.99 |
| 帧到确认文字及最终GPU模糊 r=8 | 281.60 / 323.79 / 340.28 |
| GPU模糊场景中的后台模糊 | 4.89 / 9.23 / 18.87 |

OCR模型准备约3.05秒，首次整屏模糊帧786.50ms，均不在30帧统计内。前次GPU OCR加CPU模糊最终中位315.25ms，本次281.60ms；OCR处理时间也有运行波动，不能把全差值只归因于滤波核心。剩余总体延迟主要仍包含OCR、IPC、差分与20ms轮询。没有测实际截图采集、身份/摄像头、应用追踪、DWM合成与显示器扫描输出，不把该表称为真实设备端到端延迟或准确率证明。

## 自检与回归

在已准备的仓库根目录执行：

```powershell
.\视界盾桌面防护\.venv\Scripts\python.exe .\视界盾桌面防护\gpu_blur_check.py --radius 8 --samples 10
```

该命令只用虚构像素，核对原CPU结果、输入不变和每次两个GPU核心事件；无GPU时明确失败，不把CPU回退标为GPU成功。半径参数为1–128。输出不保存图像或运行数据。生产使用`--diagnostics`的心跳查看`blur_backend`、`blur_device`、`blur_gpu_ms`及`blur_fallback`；核心时间不含传输，后台`blur_ms`含传输与首次初始化。

桌面245项、身份9项回归通过，共254项，无跳过，包括真实GPU像素核对、单行/单列/小图/半径1、2、8、16、32、128、通道顺序及只读输入，另验全屏r8逐像素一致。模拟覆盖无驱动、执行失败、资源释放及重试、取消任务、关闭超时、旧帧、空输入、启动提交、应用空洞和匿名诊断。普通无GPU环境可运行模拟回归；真实GPU测试须设置`VISIONSHIELD_TEST_GPU_BLUR=1`，未设置时明确跳过2项。Python与打包配置语法检查通过。

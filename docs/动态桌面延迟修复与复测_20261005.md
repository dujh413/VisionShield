# 动态桌面延迟修复与复测

日期：2026-10-05。基线为最新打包分支 `build/windows-exe-test-20261004` 的 `8b5c54a`，不以尚未合并更新的 main 作为完整软件基线。

## 实施顺序与保护条件

1. 精确三通道差分生成多个区域，默认最多4个、总面积35%；超限仍整屏。变化文字行完整重识别，间接纳入文字时不反复添加64像素上下文；共享裁剪边界按半开区间处理，避免相邻文字行被无限串联。8次局部更新或15秒后仍完整刷新。
2. 区域校验复用一份精确差分和小型分块积分表，边界检查仍比较实际差分像素，不用有损缩采样。上下文只缓存几何，文字与分类每次来自当前结果；未知标签的旧依赖保持到新结果确实覆盖，重复缓存不累积副本。
3. 模糊计算在后台线程完成，重叠框合并；只复制待处理的局部区域。相同区域像素复用结果，其他地方变化不重新生成此区域。显示前精确核对原像素与几何，未完成、失效或异常区域立即使用不透明深色覆盖。保持原有32像素级像素化、3×3 GaussianBlur和0.45压暗流程。
4. OCR只允许一个在途请求。忙碌时最新待处理帧留在本进程，结果返回后才序列化最新帧；稳定画面每3秒提交刷新，采集仍按原100ms周期运行，文字变化不被采样阈值忽略。停止失败阻止重复启动，后台模糊关闭后丢弃已取消的完成结果。
5. 增加可选分阶段诊断及虚构样本基准，不将图片、文字原文、个人模板写入诊断。

原模型、检测分辨率、DirectML四行批量、规则阈值、身份判断和安全稳定1秒恢复条件保持原值。没有通过降低文字清晰度、放宽缓存有效性或缩短保护等待取得加速。

空检测、空文字和低置信度会保留未知区域；真实空白也可能被保守处理。只有新的有效覆盖能解除未知保护。区域缓存有效不等于OCR模型识别出了所有文字；本轮不能证明所有隐私类别均有相同准确率。

## 验证证据

测试环境：Windows、Intel Core i9-14900HX、Python3.12.14、NumPy2.3.5、PySide6 6.11.2、OpenCV4.10.0。实际模型对照使用RapidOCR1.4.4内的同一组PP-OCRv4模型，ORT1.30.0 CPU provider；不是原测试设备或生产DirectML的成绩。

2560×1600虚构画面两处验证码变化，共8行文字，每种实现30次；修改前后全部保留8行，并正确更新两个验证码、保留虚构手机号与邮箱。下表仅计增量模块与模型处理，不含实际截图、摄像头、IPC、合成器及显示器输出。

| 指标 | 原实现 | 新实现 |
|---|---:|---:|
| 变化处理模式 | 整屏 | 两个局部区域 |
| 进入OCR的面积比例 | 100% | 6.625% |
| 中位耗时 | 303.35ms | 235.48ms |
| P95 | 315.20ms | 267.20ms |
| 首次变化处理 | 411.93ms | 577.68ms |
| 最大耗时 | 411.93ms | 577.68ms |

新路径稳态更快，但首次局部路径仍有较高峰值；不能声称最大延迟已经下降，生产DirectML与完整设备链路仍需验收。初始化和尺寸首次开销与暖机后的处理分开统计。

140行虚构文字的区域校验，10次计时（各自预热2次，图像复制不计入计时）：update中位42.44→8.14ms；accept中位63.78→9.15ms。单独两远点几何复现从整屏降为两个129×129裁剪，总面积0.813%；这只证明工作量减少，不是通用OCR速度提升比例。

实际CPU模型子进程验证：快速提交61个虚构帧请求，只有第1与第61帧被传送和处理；两个结果分别为full与partial，第二个验证码正确更新，分阶段元数据存在，停止后进程结束。没有采集真实桌面或摄像头。

133项桌面回归与9项摄像头身份回归全部通过，无跳过项。包含实际离屏Qt绘制、异步旧模糊结果拒绝、单像素变化、远距离与密集文字行变化、空/低置信度结果、未知标签上下文、重复缓存、尺寸变化、摄像头状态、登记与资源清理。另通过实际CPU模型子进程验证及全部源码语法、Git差异检查。

## 复测方法

先从托盘退出旧实例。在已准备依赖和模型的仓库根目录运行：

```powershell
.\视界盾桌面防护\.venv\Scripts\python.exe .\VisionShield.py --diagnostics
```

新版打包文件也支持 `VisionShield.exe --diagnostics`。先退出旧进程再启动，现有单实例不会自动切换诊断设置。源码日志在桌面模块忽略的records下；打包版在当前用户LOCALAPPDATA的VisionShield/records下。只在显式开启时添加performance目录：events.jsonl与每秒heartbeat.csv。

记录：采集时间、排队与截图到推理时间、差分、预处理、检测、裁剪、识别、DirectML批次数与宽度、结果接受/拒绝、接收延迟、区域校验、控制回调、模糊计算及paintEvent耗时。paintEvent不包含系统合成器和显示器扫描输出，不能直接当成完整旁观风险响应时间。

在桌面模块目录运行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -p 'test_*.py' -v
.\.venv\Scripts\python.exe benchmark_pipeline_perf.py --samples 30
.\.venv\Scripts\python.exe benchmark_pipeline_perf.py --cpu --samples 30
```

基准只生成虚构文字，不打开摄像头、不读取真实桌面。可用 `--baseline` 指向另一个保持8b5c54a源码的目录，比较同模型下旧/新增量和区域校验；输出实际provider、初始化、首次、P95、最大耗时及虚构样本正确性。预设8行不能代表复杂140行桌面或所有应用。

生产主链路仍以OCR为文字来源；UIA/Win32读取保留现有独立模块，尚未替代未完成覆盖的OCR。共享内存和扩大推理批量须先根据新增阶段数据评估，不在缺乏设备验证时改变默认后端。源码同步后还需重建完整软件目录，已有exe不会自动更新。

# 构建验收与过期产物清理

用户要求每次搭建后删减一天前已经被替代且不再需要的内容。本流程将“一天前”定义为超过24小时。源码、说明和个人数据不能仅由日期判定是否需要；可重复生成的已识别构建产物可以按保留策略清理。

## 日常构建

```powershell
& .\packaging\Build.ps1 -Python '完整路径\python.exe' -OutputName 'windows-版本名称'
```

依次进行PyInstaller构建、实际exe验收、旧构建清理。包验收会打开摄像头并进行两轮启停及捕获排除验证，不能同时运行其他摄像头测试。验收失败或超时会停止流程，保留构建目录便于排查，不删除旧包。

验收报告写入被Git忽略的test_artifacts。通过后生成dist/.verified中的本机凭证，包含包名称、exe哈希、通过状态和UTC时间；凭证也不上传GitHub。清理前重新核对当前exe哈希，避免把陈旧验收结果用于已改变的软件。

当前包与最近一个已验收的回退包始终保留，关联的构建目录及相同exe哈希的zip也保留。没有回退凭证时只保留已验收当前包，其他未满24小时的包仍自然保留；积累两个成功构建后会形成固定回退版本。

## 清理边界

| 内容 | 行为 |
|---|---|
| dist/windows-* 中包含VisionShield/VisionShield.exe的旧包 | 非当前/回退且所有内容超过24小时，才可删除 |
| build/windows-* 中有PyInstaller Analysis-00.toc的旧工作目录 | 同样按保留版本与24小时处理 |
| dist/VisionShield-Windows-*.zip | 识别exe条目，核对保留包哈希；旧且已被替代才删除 |
| 当前、最近已验收回退、正在运行的软件目录 | 保留 |
| 新产物、陌生目录、无法解析的zip | 保留，避免猜测用途 |
| 符号链接、目录联接等重解析点 | 整个候选跳过，不跨边界删除 |
| 旧软件目录内意外混入private、records、.venv、截图目录或.npz模板 | 整个候选跳过，避免按日期删除个人数据 |
| 源码、模型、.venv、private、records、用户目录 | 不进入自动清理范围 |
| 测试报告及项目文档 | 保留需要追溯的记录，修正过时说明；不按日期盲删 |

路径必须是正式仓库dist/build的直接子项；递归删除前检查绝对目标和内部重解析点。操作只使用PowerShell的LiteralPath，不把路径交给其他shell。删除记录保存在test_artifacts/cleanup-*.json。

## 单独检查

只验收一个已存在的包：

```powershell
& .\packaging\Verify-Package.ps1 -OutputName 'windows-版本名称'
```

预览将删除哪些内容：

```powershell
& .\packaging\Clean-Artifacts.ps1 -CurrentOutput 'windows-版本名称'
```

确认当前包已经通过验收后执行清理：

```powershell
& .\packaging\Clean-Artifacts.ps1 -CurrentOutput 'windows-版本名称' -Apply
```

清理安全回归测试：

```powershell
& .\packaging\Test-Cleanup.ps1
```

该测试使用独立虚构临时目录，验证预览不删除、24小时限制、当前/回退保留、联接隔离、个人数据保留和验收后exe变化拒绝，不操作正式软件数据。

这套流程由构建命令触发；不会在会话之外自动运行，也不代表保存源码就会自动构建或同步GitHub。

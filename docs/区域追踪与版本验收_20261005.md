# 应用区域追踪与版本验收

本轮将固定比例校准升级为用户框选后的控件/视觉特征追踪，并将此前已验证的源码链同步到main。仓库保持私有，尚不创建Release。

## 操作

暂停防护，打开目标应用，在设置中选择“框选并追踪应用区域…”，拖动框选要保护的部分。建议包含稳定容器边界或图标；完全空白、重复图案或只有滚动文字的区域可能无法建立稳定视觉特征。确认后重新启用防护。最多保存20个应用策略，清除应用校准后可以重新选择；也可选择应用整窗保护。

窗口移动时跟随当前控件边界；窗口内部控件移动或缩放时重新获取边界。无可访问控件时，在所属窗口内匹配ORB描述子，用RANSAC估计平移与缩放，匹配不唯一时拒绝结果。选区丢失、超时或不能可靠定位时，风险期间扩大到所属窗口，不沿用旧坐标。恢复仍由机主确认及风险消失状态控制。

## 实现

| 模块 | 责任 |
|---|---|
| scope_picker.py | 用户框选应用区域，提交初始区域与窗口身份 |
| region_worker.py | 独立进程校准及UIA查询，超时关闭，队列有界 |
| region_anchor.py | Win32子控件或UIA结构路径，读取边界，避免读取Name/Value |
| region_features.py | 最多96个ORB特征，局部描述子、几何校验、重复匹配排除 |
| region_tracker.py | 绑定实际窗口和进程，重定位、有效期、超时及回退 |
| app_scope.py | 按当前选区计算遮蔽范围，减去前景遮挡，旧坐标失效处理 |

结构锚点保存无文本的控件类、控件ID及路径，视觉描述子和当前句柄/PID只在内存中。暂停释放追踪进程；软件重启后纯视觉选区需要重新选择，结构锚点只在唯一候选窗口尝试恢复。采用最新帧缓存，不累积截图，不保存OCR原文。视觉特征不是语义模型，不能理解用户究竟想保护哪段会话。

## 验证证据

桌面模块102项自动测试、摄像头模块9项测试通过；包含选区内移动、缩放、特征消失、重复图案拒绝、同类多窗口隔离、持久化边界和旧校准迁移。清理测试覆盖预览、24小时门限、回退包保留、目录联接排除及哈希变更拒绝。

真实Win32测试窗口通过隔离校准进程建立锚点。初始位置、整体拖动、内部区域移动、调整大小和文字变化后，控件边界误差均为0像素；真实屏幕采集的视觉区域内部移动误差约1.1像素；特征移除后转为所属窗口保护。此处使用虚构测试界面，不代表所有第三方应用都已兼容。

该测试的单次操作耗时约39–60ms，包含屏幕抓取与范围计算，不能解释为整个系统风险到显示的端到端延迟，也不保证500ms内完成任意OCR。打包流程另外验证实际.exe中的隔离校准、窗口移动、内部区域移动/缩放及遮蔽映射，以及原有11项软件包检查和两轮启停；失败不清理旧包。

## 当前边界

仅主显示器；纯视觉窗口部分移出主屏、特征重复或完全更换时扩大保护。UIA接口可能被第三方应用禁用或阻塞，后台超时后终止查询并回退。实际微信、QQ、浏览器版本仍应分别验证，不能宣称全客户端语义适配。摄像头多人真实测试需另外记录，合成窗口测试不验证身份识别准确率。

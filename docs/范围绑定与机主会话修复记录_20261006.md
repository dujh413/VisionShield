# 范围绑定与机主会话修复记录

日期：2026-10-06。基于 `55ee324` 继续检查指定范围越界、主界面闪烁和身后旁人风险。本文区分已复现的程序缺陷、原生窗口验证及尚未通过的实人检测。

## 修复内容

### 整窗配置不再在重启后自动改绑

旧配置保存时移除本次窗口句柄，重新加载后只要某应用恰好剩一个可见窗口，就可能保护那个窗口。例如先选择A，重启后A和B同时存在时不保护，A关闭后却改为保护未选择的B。

当前整窗配置必须具有本次明确选择的窗口句柄和进程绑定。软件重启后保留配置提示，但暂停该整窗保护，要求在设置中重新点击目标窗口；不会猜测哪一个窗口是原目标。当前会话内拖动、缩放及暂时最小化不会改绑同应用另一窗口。未设置指定范围时仍保留自动应用与内容保护。

主界面与设置页都说明重启后重新选窗；强度仍使用水平滑杆，不要求填写数值。150%缩放下用虚构配置渲染检查，说明和操作入口可见，设置内容可以滚动。

### 首次截图排除验证不再冻结旧遮罩

旧验证等待约350ms期间，控制器停止常规刷新。此时目标窗口移动或主界面移到范围内，遮罩可能停留在旧坐标。

现在验证等待期间每20ms重新核对许可范围。窗口移动、最小化、遮挡关系改变、原生控件移动、非原生选区的客户区像素改变、用户关闭效果或修改配置，都会取消本次验证、清空旧遮罩并隐藏，之后根据新范围重试。不会因范围变化把保护扩大为整窗或整屏，也不把正常取消写成持久启动错误。

探针本身的小青色窗口可能改变无关系统窗口的排序，因此比较实际许可遮罩，而不是把每一次无关窗口排序变化都当成失败。仍必须完成真正的mss青色像素检查，不能以范围稳定代替截图排除验证。

UIA/视觉路径在这个短等待期间保持初始范围证明，不轮询或提交新的异步定位任务；同时继续检查实时原生坐标和新截图的客户区像素，仅忽略预期青色测试点。正常运行的异步任务与0.8秒定位有效期不变。

### 机主姿态宽限不能被另一尺寸的人脸继承

已确认机主转头时原有最多2秒的姿态宽限保留。旧判断只看中心距离：远处小脸出现在原机主中心附近，即使面积缩小约75倍、跟踪器已经生成另一条轨迹，仍可能输出安全状态。

当前还要求脸框面积与最后确认机主相差不超过2.5倍，与短时跟踪器的尺寸连续性标准一致。明显变小或变大的替代脸立即撤销宽限并请求保护；不会把不可辨认的脸直接称为已确认旁人。正常偏头、低头的有界宽限继续保留。

另修复过期会话先续期的问题：最后机主确认超过宽限时间或时间倒退时，先清除会话，再累计5次新匹配。有效宽限内的机主返回仍可快速重新确认，无需重新登记或覆盖模板。

### 减少主线程重复计算

桌面截图每次分配独占的新像素数组并标记只读。UIA范围追踪对同一帧、同一客户区只计算一次精确像素摘要；新帧、几何或配置变化立即重算。可写数组和只读视图不使用这个缓存，避免别名修改像素后复用旧坐标。缓存只保留当前帧的摘要，不累积截图，也不延长定位有效期。

虚构2560×1600图像连续解析10次：摘要计算10次降为1次，本机合计52.85ms降为5.57ms，范围结果相同。这是局部主线程开销测试，不是整套防护的响应时间或内存结果。

# 协作启动与同步

## 首次准备

适用于 Windows x64 / Python 3.12。不开发的使用者直接下载 [Release](https://github.com/dujh413/VisionShield/releases)，无需 Python。开发者准备公开源码：

```powershell
git clone https://github.com/dujh413/VisionShield.git
Set-Location -LiteralPath './VisionShield'
py -3.12 -m venv './视界盾桌面防护/.venv'
& './视界盾桌面防护/.venv/Scripts/python.exe' -m pip install --upgrade pip
& './视界盾桌面防护/.venv/Scripts/python.exe' -m pip install -r './packaging/requirements-build.txt'
& './视界盾桌面防护/.venv/Scripts/python.exe' -m pip install --force-reinstall --no-deps onnxruntime-directml==1.24.4
& './视界盾桌面防护/.venv/Scripts/python.exe' './视界盾桌面防护/prepare_fast_models.py'
```

下载软件ZIP并核对同一Release的SHA256。把解压目录 `_internal/视界盾开发/models` 的三个公共ONNX模型复制到源码 `视界盾开发/models`：2023mar与2026may两版YuNet、2021dec SFace。不要复制使用者的private、records或个人模板。动态YuNet也可用 `视界盾开发/prepare_face_model.py` 从固定官方提交下载并核对摘要。

当前整体软件不依赖实验Paddle或MediaPipe。最后重装DirectML解决两个ONNX Runtime发行包共享模块名的问题。检查实际导入并运行：

```powershell
& './视界盾桌面防护/.venv/Scripts/python.exe' -c "import cv2, onnxruntime as ort; print(cv2.__version__, ort.__version__, ort.get_available_providers())"
& './视界盾桌面防护/.venv/Scripts/python.exe' './VisionShield.py'
```

预期OpenCV 4.10.0、ORT 1.24.4，GPU可用性取决于设备，程序可回退CPU。也可双击根目录启动视界盾.cmd。首次登记在设置中由本人操作，日常自动读本机模板，不需要逐次指定机主。独立诊断脚本和回归测试继续用于排查。

## 日常修改与同步

先查看git status，处理自己的未提交内容，再获取最新远端。所有者在main维护时：

```powershell
git pull --ff-only origin main
# 修改、调试并运行与改动相关的验证
git diff --check
git add -- '具体修改的文件'
git commit -m '说明实际改动'
git push origin main
```

拉取或推送因队友更新失败时，先获取并处理冲突，不强推。队友建立任务分支并推送该分支，在GitHub发起PR；main要求所有者代码审查，新提交使旧审批失效。普通访客可以fork、提交Issue或PR，没有源仓库写权限。

本机正式目录仍为 `D:/ai比赛/VisionShield`；原环境和模型由忽略的联接复用，不作为另一份源码入口。其他成员使用自己的克隆目录。助手在授权范围内修改后验证、提交、同步；会话结束后不会持续自动同步。

## 验证、更新与分工

A负责人脸检测和机主状态，B负责采集、OCR、界面及封装，C负责敏感规则和虚构样本验收。本机接口数据带序号、时间和覆盖状态，过期结果不直接用于恢复。

使用虚构内容验收，分别记录推理、采集到结果、风险到遮罩和完整端到端时间。单元测试、包检查、实人双人效果分别记录。默认不增加画面预览或原文历史。

源文件修改后可直接调试。对外软件必须经[构建与包验收](Windows测试版打包说明.md)，再按[发行模板](../packaging/release/README.md)生成新版本并发布Release。旧exe不会自动变成新版；更新时完整替换程序目录，不将本机用户数据打进包。

提交源码、依赖、文档和虚构样本。环境、模型、截图、面部模板、密钥、日志、dist/build不进入Git，不用git add -f绕过。提交前检查git diff --cached。公开仓库的所有可达分支和历史可以被读取；删除当前文件不等于清除历史敏感数据。

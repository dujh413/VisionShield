## 2. 你会看到什么

| 显示 | 含义 |
|---|---|
| ID数字 | 短期轨迹编号，不是生物身份 |
| 绿色 OWNER | 用户手动选中且当前关联可靠 |
| 橙色 OTHER | 当前不是已确认机主的人员 |
| 红色 UNCERTAIN | 区域重叠或关联竞争，不能选为机主 |
| UNSELECTED | 尚未手动指定 |
| LOST_RECONFIRM | 机主漏检、关联不确定或结果间隔过长，需要重新点击 |
| PROTECT_REQUEST=1 | 建议保护的测试信号 |
| PROTECT_REQUEST=0 | 手动确认的机主是当前唯一检测目标 |

这是“第二张脸即保护”的初始基线，只输出请求，尚未接入B的敏感字段界面。它不包含姿态风险、持久身份或活体认证。

## 3. 按顺序操作（约30—45分钟）

1. 一人进入画面，鼠标左键点击自己的脸框。检查变成绿色 OWNER。
2. 缓慢左右移动、轻微转头。检查绿色标记仍跟随本人；若掉脸，记录条件并重新点击。
3. 第二人进入，与本人保持分开。检查有两个框，第二人不是 OWNER，PROTECT_REQUEST变为1。
4. 第二人缓慢移动或离开。检查角色不交换；只有机主时请求可回到0。
5. 机主离开，让第二人留下。检查提示 LOST_RECONFIRM，剩余的人不会自动变机主。
6. 机主回来。手动模式应保持未确认，必须点击本人才能重新确认。
7. 两人靠近、交叉或遮挡。检查出现不确定时解除角色绑定；分开后重新点击。
8. 按 R 清除选择；按 Q/Esc 或关闭窗口退出。再次启动检查摄像头能打开。

每组操作记录日志相对时间和真实人员安排。若发生绿色角色错误跟随另一人，立即按R并标记失败；不能只记录成功片段。

## 4. 输出与验收

records目录自动生成owner开头CSV和摘要，记录选择、丢失、重置、轨迹与保护请求，不保存画面。帧、选择和丢失事件通过同一试次时间线对应。

- [ ] 两人同框可以检测到，真人标签与日志分别保存。
- [ ] 分开的缓慢移动下，机主角色基本稳定。
- [ ] 机主离开后不自动转移给他人。
- [ ] 回来后必须重新点击。
- [ ] 歧义或漏检能触发重新确认。
- [ ] 已知失败情况记录清楚。

当前几何门限是开发起始配置，未针对你的场景校准。纯位置关联仍可能换人；未检测出的旁观者也无法触发“第二张脸”信号。核心闭环后增加姿态、可靠性与独立身份验证。

# 视界盾：快速文字获取与最终软件集成

## 一、路线调整

最终交付仍是Windows封装软件。文字模块不再要求所有文字都经过OCR，而是：

```text
可见应用窗口
    ├─ 支持UI Automation TextPattern → 读取可见文字范围和位置
    ├─ 标准Windows Edit → 读取视口内文字行
    └─ 自绘控件、图片文字、接口缺失/超时 → 变化区OCR补充
              ↓
    敏感规则与来源/覆盖/过期检查
              ↓
    结合旁观风险与遮罩控制
```

UIA只读应用公开的无障碍信息；不注入应用，不扫描进程内存，不使用键盘记录或剪贴板采集。TextPattern使用GetVisibleRanges，标准Edit使用可见行消息，不读取整个文档的隐藏内容或密码框。
UIA公开范围和文字位置取决于应用提供器；窗口遮挡、部分可见文字、长行截断和复杂自绘内容仍需单独验收，不能将提供器的结果视为整屏完整性证明。

接口依据：[Microsoft可见文字范围说明](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-usingtextrangeobjects)。

## 二、当前实现范围

| 文件 | 用途 |
|---|---|
| native_text.py | 独立进程运行UIA/标准Edit可见行读取，限制遍历预算 |
| hybrid_text_test.py | 快速路径与OCR路径并行验收，显示类别和来源 |
| native_text_demo.py | 可编辑的虚构标准Windows文本控件 |
| native_text_check.py | 只读虚构控件的速度与正确性自检 |
| ocr_worker.py | 保留现有局部OCR作为补充 |
| requirements-extra.txt | 新增无障碍读取依赖版本 |

混合预览目前加速一个前排可见应用窗口；OCR同时补充主屏其他内容。它不等于已实现所有窗口的快速直读，也尚未接入桌面遮罩。不会把OCR结果当作当前快照已经同步完成的定位结果。

## 三、先验证快速路径

关闭旧OCR预览，打开PowerShell：

```powershell
Set-Location -LiteralPath 'D:\ai比赛\VisionShield\视界盾桌面防护'
.\.venv\Scripts\python.exe hybrid_text_test.py --demo
```

会出现两个窗口：混合结果窗口和可编辑的虚构文本窗口。把它们并排放在主屏，避免覆盖测试文字。

1. 等初始化完成，左栏应出现手机号、验证码、邮箱与普通句子。
2. 修改虚构验证码，观察左栏自动更新及读取/调度耗时。
3. 左栏使用直读来源，右栏是OCR快照补充；两个来源时间不同，不把右栏当实时结果。
4. 确认敏感类别与OCR模式一致。
5. 关闭结果窗口，后台进程与测试窗口应退出。

自检：

```powershell
.\.venv\Scripts\python.exe native_text_check.py
```

2026-10-02优化后，这台电脑标准Edit虚构4行测试：10次正确读取；预热后的8次读取中位2.2毫秒，含通信及界面轮询中位16毫秒、最大31毫秒；首次请求约1219毫秒。标准Edit现在先走Win32可见行读取，避免先进入可能卡住的UIA提供器。首次初始化与稳态分开统计。此数据不代表任意应用、大文档或整屏能力。
读取得分不是OCR置信度；原型为规则兼容使用confidence=1.0，但界面显示来源，不将其作为百分之百正确的概率。

## 四、再测实际应用

```powershell
.\.venv\Scripts\python.exe hybrid_text_test.py
```

将包含虚构文字的记事本、浏览器或聊天窗口置于前排并保持可见。程序排除自身窗口，尝试读取前排应用。

记录应用和版本、来源、首次加载时间、稳态耗时、文字完整性、窗口移动/滚动后的坐标正确性、低于500毫秒的比例。左栏无文字、超预算或不完整时，右栏OCR继续补充；不能宣称快速路径已完整覆盖。
应用UIA提供器可能卡住。读取在独立进程中，主界面不等待COM；1.5秒未及时响应时清除快速结果、标出降级。对受权限限制的应用不自动请求管理员权限。

## 五、500毫秒指标怎样验收

- 采集周期：独立线程每100毫秒尝试采集，主界面每20毫秒检查结果，不等于每100毫秒完成推理。
- 支持应用：目标为初始化后，文本读取加规则判定的P95低于500毫秒。
- 从任意时刻内容出现到结果返回：包括等待轮询、截图、进程通信、推理、规则和显示，必须测端到端延迟。直读当前在取到屏幕帧后发请求，其16毫秒测试不含这一轮之前的等待与截图。
- 图片/自绘内容：已接入ONNX PP-OCRv4与DirectML，检测和识别均使用GPU，固定尺寸和批量提前预热，识别裁剪保留原始分辨率。整屏默认检测最长边1536；小字漏检时可对照2048配置。最新受控测试和复测命令见实时识别优化与验收.md，仍有超过500毫秒的峰值，需要按真实应用统计。
- 旁观风险触发：使用有效缓存可独立触发遮罩，不等待新OCR。未知区域临时保护是独立策略，不能作为“文字已快速识别”的证据。

## 六、最终封装接口

统一文本项保留text、polygon、source、window_id、frame/sequence、captured_at/finished_at、coverage及expiry。规则只处理内存文字，遮罩控制必须先检查位置与时间有效性。不同来源若不同步，禁止简单拼接后声称坐标有效。

软件内部管理摄像头、直读、OCR和遮罩进程；最终用户只使用一个入口。打包时包括UIA依赖及其原生组件、OCR模型、机主模型，并验证新机器的权限、缩放与兼容性。当前脚本是开发验收入口，不是最终用户操作流程。

预览不保存原文和截图。依赖安装产生库文件，模型副本及接口类型缓存会保留，不含本程序主动保存的桌面内容；内存处理不代表系统安全擦除。

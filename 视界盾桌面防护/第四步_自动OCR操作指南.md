# 第四步：自动OCR与文字框定位

默认运行ocr_test.py：自动采集主屏，后台进程使用本地ONNX版PP-OCRv4检测与识别模型，支持DirectML GPU推理。显示文字框及识别文字，不启动遮罩。加--sensitive可显示已有敏感规则结果；加--paddle可对照原PP-OCRv5 CPU后端。

## 1. 启动

关闭第三步screen_capture_test.py预览，在PowerShell执行：

```powershell
Set-Location -LiteralPath 'D:\ai比赛\VisionShield\视界盾桌面防护'
.\.venv\Scripts\python.exe ocr_test.py
```

等待模型初始化和固定尺寸预热；界面显示就绪后进入运行阶段。独立线程每100毫秒尝试采集，界面每20毫秒检查结果；这两个周期不代表OCR推理耗时。之后自动采集，不用截图或框选。

## 2. 窗口含义

- 左侧显示已完成OCR的桌面快照，绿色框定位文字，数字对应右侧列表。
- 右侧显示本帧识别文字与置信度，仅保留当前结果，不保存到文件。
- 顶部显示快照帧号、推理耗时、距采集已过多久。
- 完全相同的画面会显示“未变化，复用结果”，跳过重复OCR；任何像素变化都会重新识别。不会因此将旧结果用于已变化的画面。
- 小范围变化显示“变化区OCR”，顶部列出处理面积；变化框会加边距并纳入相交旧文字行，替换变化区旧结果，其他区域复用。
- 首帧、尺寸改变、变化区域超过屏幕35%，或连续8次局部更新后的下一次变化，回退“整屏OCR”。这是开发起点；仍需实际桌面验收小字和边界漏检。

OCR比采集慢时，丢弃队列中的旧帧；输入最多1帧、输出最多2条消息。预览不会强行把旧文字框套在新桌面上。它是诊断快照，尚不是实时保护效果。

## 3. 验收（约15分钟）

在主屏记事本显示虚构内容，字体先设18—24号：

```text
视界盾 OCR 本地测试
测试手机号：13800138000
验证码：246810
邮箱：demo@example.com
今天下午一起去图书馆。
```

按顺序执行：

1. 记事本放在主屏，保持静止，等待新结果。
2. 看左侧绿框是否包住对应行；看右侧是否准确识别中文、数字、邮箱。
3. 移动记事本，停止移动后等待更新，检查框与新位置对应。
4. 把字体改为12号，记录小字是否漏检或识别错误。
5. 更换深色主题，记录颜色变化后的识别效果。
6. 在聊天输入框中输入同样的虚构内容，不必发送给别人，检查气泡/输入框文字。
7. 关闭OCR窗口，再启动一次，确认能释放并重新运行。

不要求本阶段发现所有敏感信息；只记录文字识别正确性、定位及延迟。框与右侧列表中的文字都来自同一张快照。

## 4. 保存哪些内容

正常运行不保存桌面截图、识别原文或OCR历史。右侧文字可见于调试窗口，请使用虚构测试内容。Python/操作系统内存管理不等同于安全擦除。

默认ONNX模型保存在项目models/rapid_onnx目录，运行不下载模型。原Paddle对照后端为绕过Windows中文路径问题，会另复制模型到：

```text
%LOCALAPPDATA%\VisionShield\ocr_models
```

这里只存模型及校验标记，不存桌面画面、聊天原文或面部模板。运行使用显式本地模型路径，断网运行仍需你实测确认。

## 5. 自检与排错

下面只在内存生成虚构图像，并走后台进程识别，不采集桌面：

```powershell
.\.venv\Scripts\python.exe ocr_test.py --check
```

成功应显示：Synthetic OCR lines: 4，Required tokens found: True，以及Unchanged-frame reuse: PASS。2026-10-02实测通过；这不是完整主屏的速度或准确率。

- 字太小识别不好：先放大验证，再记录12号字体失败样例；之后再调整检测分辨率。
- ONNX模型缺失：运行prepare_fast_models.py。Paddle对照模型缺失才运行prepare_models.py。
- OCR异常或进程退出：保留终端报错，不继续接遮罩。
- 预览自身出现在识别中：记录系统设置；本脚本已请求排除自身，但实际排除效果需要观察。不要据此认为第六步遮罩排除已通过。

## 6. 本轮交付

记录字体大小、主题、正确/错误行、漏检、框是否偏移、顶部推理耗时。不要记录真实聊天原文。

满足普通字号基本可读、文字框对应、能自动更新、正常退出后，再进入第五步敏感规则判断。

## 7. 局部更新优化的验收

关闭旧进程，重新运行ocr_test.py。在记事本仅把验证码246810改成135790，等结果更新：

- 应显示“变化区OCR”，并列出处理面积；若变化分散或区域过大则显示整屏OCR。
- 旧246810应从本次结果中消失，新135790应出现。
- 未变化的其他行仍存在；文字框仍对应当前显示的快照。
- 清空该行后，旧文字与框应移除。
- 移动/滚动窗口后，检查旧位置不能继续留下错误文字框。

输入光标闪烁、系统时钟或其他动画也可能触发更新；多个远处分散变化会扩大重识别范围，因此真实桌面的提速不保证与虚构样本相同。

原Paddle CPU测试曾出现局部约953毫秒、整屏约4625毫秒。当前默认改为ONNX GPU；2026-10-02最新普通字号2560×1600虚构样本5次，整屏中位340.4毫秒、最大474.0毫秒，变化区中位388.9毫秒、最大560.7毫秒。关键文字正确，新验证码替换旧值。这些是暖机后的推理/增量处理耗时，不含完整采集和显示；不能作为所有应用500毫秒保证。详见实时识别优化与验收.md。

开发自检：

```powershell
.\.venv\Scripts\python.exe -m unittest -v test_incremental_ocr
.\.venv\Scripts\python.exe benchmark_fast_text.py
```

上述测试不采集真实桌面，不写入截图或原文。本版只保留上一次图像和文字结果，未新增历史截图缓存。

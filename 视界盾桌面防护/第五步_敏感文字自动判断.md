# 第五步：自动标记敏感文字行

最终目标为封装的视界盾软件。本轮用现有OCR预览作为验收入口；sensitive_rules.py是独立业务模块，后续主程序、遮罩和打包直接复用，不要求最终用户运行测试脚本。

## 1. 启动

关闭上一轮OCR窗口，在PowerShell执行：

```powershell
Set-Location -LiteralPath 'D:\ai比赛\VisionShield\视界盾桌面防护'
.\.venv\Scripts\python.exe ocr_test.py --sensitive
```

启动后自动采集主屏、OCR、执行规则；不用手动截图、框选或逐条确认。本步只显示定位框，不遮盖桌面，尚未连接旁观风险。

## 2. 看什么

| 颜色 | 含义 |
|---|---|
| 红框 | 命中敏感规则 |
| 橙框 | 低OCR置信度，无法确定，建议保守保护 |
| 绿框 | 未命中当前规则，不代表内容安全 |

右侧逐行显示OCR置信度、类别与命中理由。置信度是文字识别置信度，不是敏感概率。左侧框和右侧结果来自同一张OCR快照，顶部显示快照帧号和耗时。

## 3. 先测同一行

在主屏记事本，先用18—24号字显示以下虚构内容：

```text
今天下午一起去图书馆。
本次测试数字：123456
测试手机号：13800138000
邮箱：demo@example.com
验证码：246810
学号：202600001
账号：demo_user
密码：DemoPass123
地址：虚构市测试路88号
今天讨论如何修改密码
```

观察：手机号、邮箱、验证码、学号、账号、密码、地址是否红框；普通聊天、无标签的普通数字、讨论修改密码的句子是否未命中。OCR认错时先记录识别错误，不直接归为规则错误。

## 4. 再测换行

单独显示下面两行，彼此保持靠近：

```text
验证码：
246810
```

应同时标记标签行和数字行，数字行的理由为“邻近标签关联”。

再将数字移到明显远处，检查不会仅因数字格式而继续按验证码关联。空间关联只选最近、符合格式及相对位置的一个候选；多行地址、复杂聊天排版仍可能漏检，要记录失败样例。

## 5. 检查更新与困难条件

1. 把手机号替换成普通句子，等待新OCR结果，旧红框应消失。
2. 删除敏感行，检查旧框和旧文字被移除。
3. 移动、滚动窗口，检查快照中的框是否对应新位置。
4. 缩小到12号字、切换深色主题，分别记录漏检、误认、定位误差。
5. 关闭窗口退出，再启动一次。

无法读到的文字不会凭空变成规则输入；没有框不代表安全。本步不做聊天语义分类，普通私人聊天不保证被识别为敏感。

## 6. 实现及边界

- 手机号、邮箱：格式匹配；全角文字先规范化。
- 身份证：格式、出生日期可解析及校验码；没有核验真实身份或地区真实性。
- 验证码、学号、账号、密码、姓名、地址：标签赋值语境＋附近候选值。
- 低置信度：输出“无法确定”，不视为安全。
- 返回line_index、polygon、categories、reasons，不把聊天原文写入日志。

这是规则覆盖范围，不是全量隐私检测。标签省略、OCR断词、地址多行和空间关联错误都需实际验收。

## 7. 自检

```powershell
.\.venv\Scripts\python.exe -m unittest -v test_sensitive_rules test_incremental_ocr
.\.venv\Scripts\python.exe ocr_test.py --sensitive --check
```

前者测试规则与局部坐标，后者使用虚构图像测试OCR→敏感规则，不采集桌面。

本轮验收记录建议只保存：场景编号、字体/主题、预期类别、命中是否正确、误判/漏判、定位是否正确；不要记录真实聊天内容或截图。正常预览不保存原文、图像或结果历史。

本步通过后再进行第六步：不透明桌面遮罩和实际采集排除验证。

# VisionShield · 视界盾

面向公共学习与办公场景的内容级屏幕暴露防护软件。最终交付为一个Windows软件，统一管理摄像头、机主识别、文字获取、敏感判定与桌面遮罩。

产品方向：内存占用小、后台托盘运行、主界面简约。当前统一入口为`VisionShield.py`，默认不启动采集和模型；启用防护后自动同时启动摄像头机主识别和桌面OCR。发现风险时提醒机主，并模糊遮蔽敏感区域；风险稳定消失后恢复。暂停后释放后端资源。启动方式、登记和限制见[轻量后台软件设计](docs/轻量后台软件设计.md)。

桌面模块环境准备完成后，双击`启动视界盾.cmd`打开界面。

## 项目流程

启动软件 → 自动采集桌面 → 快速获取可见文字 → 判断敏感信息 → 检测旁观风险 → 自动遮盖 → 风险稳定消失后恢复。

首次登记机主由本人在设置中操作。当前软件主链路使用本地GPU OCR，机主检测与OCR并行，控制逻辑独立于OCR推理。OCR结果按区域与最新画面核对，稳定区域保留有效敏感框；变化或尚未分析的区域先临时遮蔽。UIA/Win32直读模块保留为下一阶段加速路线，尚未接入当前软件主链路。

最终交付计划为Windows `.exe` 桌面软件；本阶段完成源码整体流程，不生成或宣称已完成安装包。

## 协作流程

1. 每项任务先建Issue，写明负责人、交付内容和验收条件。
2. 从最新main创建任务分支，例如feat/owner-risk、perf/text-latency、feat/overlay-control。
3. 本机完成修改并验证后提交、推送，再创建Pull Request。
4. 由另一名成员检查修改和验证记录，之后合并main。
5. 合并后联合测试摄像头风险 → 桌面状态 → 遮罩 → 恢复，保持main可运行。

通过PR合并和同伴检查为团队约定；本次未配置强制分支保护。

## 接口约定

摄像头状态包括owner_verified、protect_request、faces_count、sequence、session、updated_at。文字结果保留text、polygon、source、frame/sequence、采集和完成时间以及覆盖状态。坐标统一为物理屏幕像素；接收端检查时效、来源和坐标有效性。不同时间来源的结果不能未经检查直接拼接。

并行开发时进一步补齐字段类型、过期阈值、异常处理和接口版本，并与实际代码一致。

## 环境与验收

环境和启动步骤见[协作启动与同步](docs/协作启动与同步.md)。每名成员独立建立虚拟环境；GPU与CPU配置分别统计性能。

用虚构样本检查小字、深色主题、连续输入、通知、聊天滚动与窗口移动。区分OCR推理耗时、文字获取端到端耗时、风险信号到遮罩耗时和完整系统响应；不把采集周期当成响应时间，不把受控样本结果作为所有应用的性能保证。

仓库为Private。由仓库所有者在Settings → Collaborators中邀请指定GitHub账户。未获授权的账户不能访问私有仓库；协作者的实际权限以GitHub设置为准。

模型使用准备脚本或约定下载方式，记录名称、版本、校验和与许可。打包配置可以提交，生成的安装包和构建目录另行管理。

# VisionShield · 视界盾

面向公共学习与办公场景的内容级屏幕暴露防护软件。最终交付为一个Windows软件，统一管理摄像头、机主识别、文字获取、敏感判定与桌面遮罩。

产品方向：内存占用小、后台托盘运行、主界面简约。当前统一入口为`VisionShield.py`，默认不启动采集和模型；启用防护后自动同时启动摄像头机主识别和桌面OCR。发现风险时提醒机主，并模糊遮蔽敏感区域；风险稳定消失后恢复。暂停后释放后端资源。启动方式、登记和限制见[轻量后台软件设计](docs/轻量后台软件设计.md)。

桌面模块环境准备完成后，双击`启动视界盾.cmd`打开界面。

主界面通过下拉框选择“模糊”或“深色遮挡”，拖动强度滑杆调整模糊效果，向右拖动使文字更难辨认；无需输入数值。效果可运行中调整。“风险时遮蔽保护范围”关闭后仍检测与提示，屏幕内容保持可见。首次默认使用适中模糊，旧空输入不会再让已勾选的遮蔽失效。具体操作及动态桌面坐标校验见[动态桌面防护与显示模式](docs/动态桌面防护与显示模式.md)。

动态桌面性能路径已加入多处局部OCR、精确区域校验缓存、后台盒式模糊与最新帧调度，保留应用范围和区域追踪。可用 `--diagnostics` 记录匿名阶段耗时；合成CPU测试及真实设备验收边界见[动态桌面延迟修复与复测](docs/动态桌面延迟修复与复测_20261005.md)。

准备桌面虚拟环境与本地模型后，在仓库根目录执行 `powershell -ExecutionPolicy Bypass -File .\Enable-GpuOcr.ps1`，修复 CPU/DirectML 发行包覆盖并验证真实 GPU OCR 算子。已启用环境不会重复下载运行时；GPU 验收与使用步骤见[GPU OCR 启用与验证](docs/GPU_OCR启用与验证_20261005.md)。

模糊自动优先使用显卡驱动的 OpenCL GPU 路径，滑杆强度映射为内部物理像素半径。GPU不可用时回退CPU计算。后台核验实际GPU执行、释放图像缓冲，暂停释放GPU会话；首次结果尚未准备好时仅在有效保护范围内使用深色保护，连续刷新尽量保留同一范围的有效模糊结果。GPU算法、实测与自检命令见[GPU模糊实现与验证](docs/GPU模糊实现与验证_20261005.md)；该报告中的数字输入说明为旧界面，当前操作以本说明为准。旧exe需要重新构建才包含本轮修改。

现已提供 Windows `.exe` 便携测试版的构建配置，包含界面、摄像头与默认 ONNX OCR 全链路；完整软件目录在本机构建，不上传二进制或个人数据。使用、重建和升级说明见[Windows测试版打包说明](docs/Windows测试版打包说明.md)。

## 项目流程

启动软件 → 自动采集桌面 → 快速获取可见文字 → 判断敏感信息 → 检测旁观风险 → 自动遮盖 → 风险稳定消失后恢复。

首次登记机主由本人在设置中操作。当前软件主链路使用本地GPU OCR，机主检测与OCR并行，控制逻辑独立于OCR推理。OCR结果按区域与最新画面核对，稳定区域保留有效敏感框；变化或尚未分析的区域先临时遮蔽。UIA/Win32直读模块保留为下一阶段加速路线，尚未接入当前软件主链路。

当前已提供Windows `.exe` 便携测试版，需要完整解压软件目录；正式安装器仍待制作。三个防护选项支持运行中修改，模糊强度通过滑杆调整。局部保护由用户框选应用的一部分，绑定窗口及控件/视觉特征，随拖动或内部布局变化重新定位；定位失效时暂停该选区遮蔽并提示重新选择。整窗保护只作用于所点窗口。设置范围后其他应用和区域保持清晰，不再叠加自动应用策略。操作和测试边界见[应用遮蔽方案](docs/应用遮蔽与姿态容错方案_20261005.md)。

暂停防护后，在设置中选择“局部保护：拖动框选区域…”或“整窗保护：点击目标窗口…”。同一应用仅保留一个范围，重新选择会替换先前范围；纯视觉选区重启后需重新框选，整窗配置重启后需重新点击目标窗口，不自动改绑同应用其他窗口。选择或清除范围会先保存设置页选项并立即应用；普通“取消”不保存尚未提交的设置页选项。清除范围后恢复默认应用与内容保护，因此需要限定范围时应保留有效选区。

继续审查发现的整窗重启误绑、首次截图排除验证时旧范围冻结、不同尺寸人脸借用机主宽限及过期会话续期已修复。只读截图使同帧追踪摘要可安全复用，减少主线程重复计算。具体复现、原生窗口/UIA验证和仍未通过的实人范围见[范围绑定与机主会话修复记录](docs/范围绑定与机主会话修复记录_20261006.md)。

后端启动环境将OpenBLAS计算线程限制为1，避免每个NumPy进程建立大量线程内存；不修改系统环境变量。真实GPU OCR虚构画面对照及此前407项回归见[后台计算线程与离线检测验证](docs/后台计算线程与离线检测验证_20261006.md)。机主人脸特征仍使用原有SFace模型与本机模板。

摄像头链路现优先使用同权重YuNet的ONNX Runtime CPU引擎，关闭空闲自旋；初始化不可用时回退原OpenCV检测器。去掉相机新帧循环内的重复100ms分区限频，加速引擎在复检小脸时仍扫描两块背景分区。公开样本的定位、身份特征兼容及扫描节拍证据见[人脸推理加速与扫描节拍验证](docs/人脸推理加速与扫描节拍验证_20261006.md)。本机r5便携包已包含上述改动并通过12项包检查、两轮启动停止及区域跟随检查；旧exe不会自动更新。严重模糊小脸仍有漏检，未达到所有身后区域500ms内检测的保证，双人实测待用户方便时进行。

本机r6进一步修复选区确认期间的窗口变化误绑，并在加速人脸引擎上交替执行镜像对比度增强，修复已确认小脸下一帧变弱时重复等待的问题。441项自动回归通过、2项条件跳过，原生选择器14项通过，冻结包13项检查及实时开关/退出检查通过。公开合成背景目标匹配由151/204增至173/204，没有丢掉先前匹配，但仍有39个额外框及严重模糊小脸漏检，不能承诺500ms内完成所有检测。完整证据与仍待实人验收的问题见[选区确认与小脸增强修复](docs/选区确认与小脸增强修复_20261006.md)。

## 协作流程

1. 每项任务先建Issue，写明负责人、交付内容和验收条件。
2. 修改前读取最新main，检查队友更新并保留本地工作。
3. 本机完成修改及必要验证，再提交并非强制同步到main。
4. 同步前再次检查远端；有冲突时先处理，不覆盖队友修改。
5. 联合测试摄像头风险 → 桌面状态 → 遮罩 → 恢复，保持main可运行。

根据所有者最新要求，本项目更新直接交付主分支，不以仅创建分支或PR作为完成。队友已有PR保留供后续审查，未经确认不自动合并。本次未配置强制分支保护。

## 接口约定

统一软件的摄像头进程传递owner_verified、owner_session_active、protect_request、stranger_detected、enrolled、faces_count、sequence及单调时钟observed_at，并累计携带last_stranger_sequence/last_stranger_observed_at。独立旧版身份接口通过本机UDP传sequence/session/updated_at，接收端另记received_at用于恢复观察时效。文字结果保留text、polygon、source、frame/sequence、采集和完成时间以及覆盖状态。坐标统一为物理屏幕像素；接收端检查时效、来源和坐标有效性。不同时间来源的结果不能未经检查直接拼接。

并行开发时进一步补齐字段类型、过期阈值、异常处理和接口版本，并与实际代码一致。
